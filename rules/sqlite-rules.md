# SQLite の大原則

適用条件: SQLite（node:sqlite・sqlite3 等）を扱うとき。使い捨ての確認コマンドも含む。

## `-wal` と `-shm` を消さない

- **本体を残して `-wal` / `-shm` だけを消してはいけない。例外はない**。`-wal` には本体にまだ統合されていない書き込みが入っている。消せばその分が失われ、本体だけが残る。**実測では発言 64 件のすべてが `-wal` 側にあり、本体は 0 件だった**
- 邪魔に見えても消さない。**捨てるときは 3 つまとめて捨て、残すときは 3 つまとめて残す**（使い捨ての DB を作り直すときは 3 つ揃えて消す。これは原則に沿う）
- 移動・コピー・退避・受け渡しも 3 つ一組で行う。**本体の大きさから中身の量は判断できない**

## 開いたら必ず閉じる

- **`close()` する**。閉じないと WAL の内容が本体に統合されず `-wal` と `-shm` が残る
- **読み取り専用で開いた場合は `close()` しても残る**。読み取り専用の接続はチェックポイントも後片付けもしないため
- **控えや退避したものを確認するときは、コピーを作ってそちらを開く**。元の置き場を増やさない

## 変えられないものはテーブルを作り直す

- **`ALTER TABLE` は列の追加と改名しかできない**。制約（`CHECK` 等）の変更・列の削除・型の変更・並べ替えはできない
- できない変更が要るときは、**新しい定義で別名のテーブルを作り、`INSERT INTO … SELECT` で写し、元を消して名前を変える**
- **索引を張り直す**。テーブルと一緒に消える
- **メンテナンスの印を置いてから行う**。途中で書き込まれると整合が崩れる。作業の前に控えを取る
