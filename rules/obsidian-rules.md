# Obsidianメモリ連携ルール

適用条件: すべてのセッション。Obsidian Vault を、プロジェクト・エージェント・端末をまたぐ永続メモリとして使う。

## Vault に置くもの・置かないもの

- **置くのは、プロジェクトをまたいで引き継ぐものだけ**。プロジェクトの索引・作業日誌・プロジェクトをまたぐ事実（環境・道具・参照先・利用者）
- **進捗・課題は置かない**。正本は各プロジェクトの status / issues
- **進め方のルールは置かない**。正本は共通ルール。プロジェクト固有のことはローカルルール
- **AI エージェントの自動メモリは使わない**。書く先を Vault に一本化する

## 読み書きの手段

- **MCP は使わない**。Vault のファイルを Read・Write・Edit で直接読み書きする（Obsidian が起動していなくてよい）
- **Vault の場所は環境変数 `AI_AGENT_OBSIDIAN_VAULT`**。ルールにパスを書かない
- **Vault のノートは、利用者に確認せずに読み書き・修正してよい**。プロジェクトの外でも同じ。既存のノートを書き換えるときも、確認は要らない

## 構造

- **Vault のフォルダ構成はこの節に従う**。「プロジェクトフォルダ構成」は当てはめない（`notes/` を置かない）
- **Vault のローカルルールは `rules/local-rules.md` に Markdown で書き、直下の `AGENTS.md` から取り込む**。Vault のセッションだけが行う運用 (cron・待受け等) を書き、フォルダ構成はこの節にだけ書く
- `index.md`: 入口。各ハブ (`!memory`・`!projects`・`!rules`) へのリンクを置く
- `about-me.md`: 利用者について (user)
- `rules/!rules.md`: ルールの目次。共通ルールを読まない AI エージェント向けの要約を、`rules/` のノートに置いてリンクする
- `memory/!memory.md`: 起動時に注入する目次。`- [[ノート名]] — 要約（type）`
- `memory/<事実>.md`: 1 ノート＝1 事実。フロントマターに type（`user` / `feedback` / `project` / `reference`）を付け、`[[!memory]]` をリンクする
- `projects/!projects.md`: プロジェクト一覧。1 行 1 件
- `projects/<プロジェクトフォルダ名>.md`: プロジェクトのノート。**進捗は書かない**
  - **frontmatter に次の鍵を、この順で置く**。分からない値は `不明` と書く
    - `id`: プロジェクトのフォルダ名
    - `title`: 日本語のプロジェクト名。README のタイトルに合わせる
    - `type`: `project`
    - `date`: プロジェクトの開始日 (yyyy-mm-dd)。ノートを作った日ではない
    - `tags`: `project`
    - `ai-agent`: 主に使う AI エージェント (`Claude Code` 等)
    - `path`: プロジェクトの場所。`/` 区切り。新しく書くときは `C:/work/…` にする
    - `repo`: リポジトリの URL。無ければ `なし`
  - **本文は、親のリンク `[[!projects]]` と `- 目的: …` の行**。場所・リポジトリ・開始日は frontmatter にだけ書き、本文に重ねない
- `plans/<計画番号>-<件名>.md`: Vault 自体の計画。プロジェクトのノートではないので、`projects/` に置かず、`!projects.md` にも載せない
- `daily/yyyy-mm-dd.md`: 作業日誌。午前・午後の 2 節に、プロジェクトごとの要点を箇条書き
  - **1 行 1 プロジェクト。行頭にプロジェクトのノートへのリンクを置く**（`- [[<プロジェクトフォルダ名>]]: 要点`）。プロジェクト名を文字だけで書かない
  - **先頭は frontmatter (`title`・`date` は yyyy-mm-dd、`tags` は `daily`) と、`# yyyy-mm-dd` の見出し**。無いファイルに追記するときは、先に足す
  - **節は `## 午前` と `## 午後` の 2 つだけ**。0〜12 時は午前、12〜24 時は午後に書く。深夜・昼・夕方・夜の節は作らない
  - **新しく作るときは、次の形で始める**

    ```markdown
    ---
    title: yyyy-mm-dd
    date: yyyy-mm-dd
    tags:
      - daily
    ---
    # yyyy-mm-dd

    ## 午前
    ```

## いつ書くか

- **プロジェクトを作ったとき、および既存のプロジェクトで作業を始めたとき**: `projects/` にそのプロジェクトのノートが無ければ作り、`!projects.md` に 1 行足す。ノート名はプロジェクトフォルダ名
- **作業の区切り**: その日の `daily/` に追記する。追記するだけで、既存の行は書き換えない。Stop フックが促す
- **プロジェクトをまたぐ新しい事実が分かったとき**: `memory/` にノートを作り、`!memory.md` に 1 行足す。既存のノートと重なれば、新しく作らずに更新する。誤りと分かったノートは消す

## 同期

- **書く前に fetch して rebase する**
- **commit と push は Stop フックが行う**。Vault に限った例外で、「重大な操作の確認方法」の対象にしない
