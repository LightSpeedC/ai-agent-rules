# Obsidianメモリ連携ルール

適用条件: すべてのセッション。Obsidian Vault を、プロジェクト・エージェント・端末をまたぐ永続メモリとして使う。

## Vault に置くもの・置かないもの

- **置くのは、プロジェクトをまたいで引き継ぐものだけ**。プロジェクトの索引・作業日誌・プロジェクトをまたぐ事実（環境・道具・参照先・利用者）
- **進捗・課題は置かない**。正本は各プロジェクトの status / issues
- **進め方のルールは置かない**。正本は共通ルール。プロジェクト固有のことはローカルルール
- **AI エージェントの自動メモリは使わない**。書く先を Vault に一本化する

## 読み書きの手段

- **MCP は使わない**。Vault のファイルを Read・Write・Edit で直接読み書きする（Obsidian が起動していなくてよい）
- **Vault の場所は環境変数 `AI_AGENT_OBSIDIAN_VAULT`**。ルールにパスを書かない
- **Vault はプロジェクトの外でも、この見出しの用途に限り確認なしで読み書きしてよい**

## 構造

- **Vault のフォルダ構成はこの節に従う**。「プロジェクトフォルダ構成」は当てはめない（`notes/` を置かない）
- **Vault のローカルルールは `rules/local-rules.md` に Markdown で書き、直下の `AGENTS.md` から取り込む**
- `memory/!memory.md`: 起動時に注入する目次。`- [[ノート名]] — 要約（type）`
- `memory/<事実>.md`: 1 ノート＝1 事実。フロントマターに type（`user` / `feedback` / `project` / `reference`）を付け、`[[!memory]]` をリンクする
- `projects/!projects.md`: プロジェクト一覧。1 行 1 件
- `projects/<プロジェクトフォルダ名>.md`: 場所（~ 表記・/ 区切り）・リポジトリ・目的・開始日。**進捗は書かない**
- `daily/yyyy-mm-dd.md`: 作業日誌。午前・午後の 2 節に、プロジェクトごとの要点を箇条書き
  - **1 行 1 プロジェクト。行頭にプロジェクトのノートへのリンクを置く**（`- [[<プロジェクトフォルダ名>]]: 要点`）。プロジェクト名を文字だけで書かない

## いつ書くか

- **プロジェクトを作ったとき、および既存のプロジェクトで作業を始めたとき**: `projects/` にそのプロジェクトのノートが無ければ作り、`!projects.md` に 1 行足す。ノート名はプロジェクトフォルダ名
- **作業の区切り**: その日の `daily/` に追記する。追記するだけで、既存の行は書き換えない。Stop フックが促す
- **プロジェクトをまたぐ新しい事実が分かったとき**: `memory/` にノートを作り、`!memory.md` に 1 行足す。既存のノートと重なれば、新しく作らずに更新する。誤りと分かったノートは消す

## 同期

- **書く前に fetch して rebase する**
- **commit と push は Stop フックが行う**。Vault に限った例外で、「重大な操作の確認方法」の対象にしない
