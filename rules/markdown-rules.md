# HTML→Markdown 変換ルール

適用条件: 既存の HTML ドキュメントを Markdown 化するとき、または GitHub 等で表示する Markdown を新規作成するとき。

## HTML と Markdown の併存

- **HTML から Markdown を作成しても、元の HTML は削除しない**。常に両方を残す
- **HTML を正とし、Markdown は HTML から生成したものとして扱う**
- **変換は `html2md` を使う**（プロジェクトを問わず共通）。PATH に入っているのでパスの指定は要らず、プロジェクト側にランチャを置く必要もない
- 変換対象は root の `README.html` と `notes/` 配下の html。`docs/` など別のフォルダは `--dir`、root 直下の README 以外は `--extra` で渡す
- **毎回すべての対象を渡す**。`--extra`・`--dir` を忘れて素で走らせると、渡さなかった html へのリンクが README 側で `.md` から `.html` に戻る（生成済みの .md が書き換わる）
- 利用方法の詳細（コマンド・オプション・変換対象の外し方・検査の読み方）は `T:/ai-agent-tools/TOOLS-USAGE.md` を参照
- **変換に使うクラス名は「HTMLデザインルール」の「クラス名」に従う**。プロジェクトごとに違う名前を使わない
- 内容を更新するときは HTML を直し、html2md を再実行して Markdown を作り直す。Markdown を直接編集しない（次の生成で上書きされる）
- **ページ全体を変換対象から外すときは `<head>` に `<meta name="md-skip">` を入れる**。要素単位で外すときは `class="md-skip"` を使う
- **ファイル名で外すときは `--exclude <名前>` を渡す**（複数回指定可。既定で `index.html` を除外する）

## SVG図の扱い

- **インライン SVG は独立ファイルに切り出し、`![](images/xxx.svg)` で参照する**。GitHub は Markdown 内のインライン SVG をサニタイズで除去するため
- **画像は Markdown ファイルと同じフォルダの `images/` に置く**
- 切り出した SVG には **`xmlns="http://www.w3.org/2000/svg"` と `width` / `height`** を付ける（単体ファイルとして開けるようにするため）
- **白背景の矩形を最初に置く**（`<rect width="100%" height="100%" fill="#ffffff"/>`）。透過のままだとダークモードで文字が読めなくなる
- **`<defs>` の id は元 HTML でページ全体一意にしていたが、切り出し後はファイル単位で一意ならよい**。短い名前に付け直してよい

## 文言の同一性

- **HTML に無い文章・記号を Markdown に足さない**。変換は記法の置き換えだけを行い、文言は同一にする
- 生成物であることの注記・補足説明・案内文を Markdown 側だけに追加しない。HTML と内容が乖離し、どちらが正か分からなくなる
- 運用上の取り決め（Markdown を直接編集しない等）は README かスクリプト内のコメントに書き、各ドキュメントの本文には入れない
- 文字を補うのは「記法の対応」表と「色分けの代替」で認めた範囲に限る。それ以外の装飾記号を独自に足さない
- **リンクテキストにファイル名を書かない**。書くと拡張子置換のときにテキストまで書き換える必要が生じ、文言が一致しなくなる

## 色分けの代替

- **色でしか区別していない情報は、Markdown では文字に落とす**。バッジの色分けは太字や記号に、グラフの凡例は色名を SVG 内に文字で入れる
- バッジの記号は太字の外に置く（`✅ **良い**`）
- **バッジの記号は、「結果の報告に絵文字を付ける」の絵文字に揃える**。`b-ok` は ✅、`b-ng` は ❌、`b-warn` は ⚠️、`b-none` は ⬜

## 記法の対応

| HTML | Markdown |
|------|----------|
| `.callout` | `> [!NOTE]` / `[!IMPORTANT]` / `[!WARNING]` / `[!CAUTION]` |
| `<section>` + `h1` の章 | `## 1. 章名` （見出しレベルを1つ下げる） |
| タイトルバー内の日付 | `> 📅 作成: ... / 更新: ...` の引用行 |
| 目次の `<ol>` バッジ | 通常の番号付きリスト＋アンカリンク |
| `<table>` | Markdown テーブル。数値列は `---:` で右寄せ |
| ボタン状のリンク（`.doclink` 等） | 通常のリンク。装飾記号は足さない |
| 段落内の `<br>` | `<br>` タグをそのまま出す |

## 日本語の強調は `**` では効かないことがある

`<strong>` を `**` にすると、**日本語では強調にならず `**` が記号のまま表示される**ことがある。CommonMark が `**` の前後の文字で開閉を判定するため。

- **開きの直後が句読点**で、その直前が通常文字だと**開かない**
- **閉じの直前が句読点**で、その直後が通常文字だと**閉じない**

実際に踏んだ文字:

| 位置 | 文字 | 壊れる書き方 |
|------|------|--------------|
| 開きの直後 | `「` | `主題は**「何が流れるか」**です` |
| 開きの直後 | `［` | `バッジは**［pwsh 7］**です` |
| 開きの直後 | `.` `-` `@` | `**.cs を渡せば通る**` ／ `**-Path では見つからない**` ／ `**@() で包む**` |
| 閉じの直前 | `。` | `**入れてください。**5.1 は…` |
| 閉じの直前 | `」` | `**「対象が何か」**で決める` |
| 閉じの直前 | `）` | `**値型（struct）**と…` |
| 閉じの直前 | `］` | `**［5.1］**<span>` |

- **該当する箇所だけ `<strong>〜</strong>` に置き換える**。GitHub は Markdown 中の HTML を解釈するので確実に太字になる
- 半角スペースを入れて成立させる方法もあるが、日本語の文中に隙間が空くので使わない
- 判定と置き換えは html2md が機械的に行う。書き手に意識させない
- <strong>上記はドキュメント（.md）の話。</strong>AIエージェント自身の応答は端末のレンダラで描画され、GitHub より判定が厳しい。応答では句点を太字の外に出すか、半角スペースで区切る

## 相互リンク

- **HTML からは HTML、Markdown からは Markdown を参照する**。同じ種類同士でリンクし、混在させない
- **例外は md-skip のページ**。Markdown が生成されないため、Markdown 側でも `.html` を指す。置き換えの除外は html2md が行うので、書き手は常に `.html` と書けばよい
- **HTML には常にリンク先を `.html` と書く**。`.md` への置き換えは変換スクリプトが行うので、HTML 側で先取りして `.md` と書かない（HTML のリンクが壊れ、Markdown 側は正しくなるため気づきにくい）
- 変換時にリンク先の拡張子を `.md` に置き換える
- **変換後の検査は html2md が行う**（Markdown 側のリンク切れ・アンカ切れ・HTML 側の `.md` 参照・HTML 側のリンク切れ・Markdown 側だけの文言・更新日）。HTML 側も独立に検査するのは、Markdown 側だけ見ると変換で `.md` になった分と区別できず見逃すため
- **バッジのある見出しのアンカは、記号の有無と、絵文字表示のセレクタ（U+FE0F）の有無で変わることがある**。記号を変えたら、外から張ったリンクを確かめる

## 生成した Markdown は GitHub のレンダラで検証する

ローカルで正しく見えても GitHub 上で壊れることがある。**推測で「直った」と判断しない。**

- **`check-markdown` を使う**（プロジェクトを問わず共通）
- Markdown を `https://api.github.com/markdown` に投げ、返る HTML に `**` が残っていないかを見る。コードブロックとコードスパンは対象外
- 認証なしは 60 回/時。`-Token` を渡すと 5000 回/時
- `ConvertTo-Json` の結果は **UTF-8 のバイト列にしてから送る**。そのまま送ると日本語が壊れる
- GitHub は `<code class="notranslate">` とクラスを付ける。`<code>` 決め打ちの正規表現では拾えない

**Why:** 閉じ側の規則だけを見て 60 件を直したと報告した後、GitHub 上では開き側の 29 箇所が壊れたままだった。ローカルの理屈と実物の表示は一致しないことがある。
