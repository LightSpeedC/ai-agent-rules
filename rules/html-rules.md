# HTMLデザインルール

## ドキュメントの保存場所と形式

- **ドキュメントは HTML で作成する。Markdown だけで作らない**（必要なら「# HTML→Markdown 変換ルール」に従って HTML から生成する）
- **README も例外ではない**。世間では `README.md` を直接書くのが通例だが、ここでは他の資料と同じく `README.html` を正とし、`README.md` は html2md による生成物にする
- **HTML は BOM 付き UTF-8 で保存する**。HTML5 は BOM を meta charset より優先するため、どのブラウザで開いても化けない。**Markdown は BOM 無し**（BOM が本文の先頭に混ざって見出しが崩れる処理系がある）
- **置き場所は読み手で決める**。外部に配るものは `docs/`、自分たちの管理用は `notes/`
- **複数ファイルに分ける読み物でなければ、root の `README.html` をそのまま公開の実体にしてよい**。`docs/` は作らない（公開の手順は「GitHub Pages 公開ルール」）
- **資料の構成案は読者にも公開し、`docs/ZZ-構成.html` に置く**（対象読者・章立ての意図・執筆方針）。`ZZ-` は本編 `01`〜・付録 `A1`〜 の後ろに並べるための接頭辞
- 公開しない検討メモ（未確定の案・費用・体制）は `notes/10_plan/` に置く
- **資料に制作の事情を書かない**。いつ書いたか・どの順で作ったか・何を守れなかったか。**判断基準は「後から読む人に価値があるか」**。書き手の反省は読者の役に立たない

## 絶対ルール: 背景は淡い色のみ

- **ページ全体・各セクションの背景は常に淡い色（白または非常に薄い色）にする**
- 濃い色は、タイトルバーや見出し(h1)の箱など**小さく限定された要素にのみ**使ってよい

## 絶対ルール: 文字色と背景色は必ずペアで成立させる

- **`color` を書く宣言ブロックには `background` も書く**（逆も同じ）。例外は body のみ
- **色の `var()` には必ずフォールバックを書く**: `var(--accent, #12224d)`
- **配色セレクタは要素構造で絞る**。`.toc a` ではなく `.toc ul a`
- **濃い背景の中の `code`・`a`・`strong`・バッジは個別に色を指定する**。`code` は白文字に反転（`background: rgba(255,255,255,0.16); color: #fff; border: none;`）
- **背景のないリンクにも文字色を明示する**（`--link: #1a4fa0`）

## 生成した HTML はコントラスト比を実測して検証する

- ブラウザでレンダリングし、`getComputedStyle` から前景色と実効背景色の比を計算する。透明な背景は親を遡り、**グラデーションは色停止点の平均**を使う
- **1.5:1 未満を0件にする**。検出目的は「読めない」（白に白・黒に黒・継承事故）。値を上げると誤検出で埋もれる
- リダイレクトページ（`meta refresh` / `location.replace`）は除外する
- **検証は `check-contrast` を使う**（プロジェクトを問わず共通）。`-Path <対象> -Recurse` で指定する。実体は PlayWright 共有環境にあり、自プロジェクトに Playwright を入れる必要はない

## レイアウトの基本寸法

- **本文の折り返し幅は `max-width: 1600px`、左右に `padding: 0 30px`** を取る。タイトルバーは全幅にし、内側の `.inner` とフッターも同じ 1600px ／ 左右 30px に揃える
- **本文は `font-size: 15.5px` / `line-height: 1.85`**。見出し・code・table のサイズは `em` の相対指定にして本文サイズに追従させる
- **余白の基準値**（実測で調整する前の初期値）: タイトルバー `34px 30px 30px` ／ フッター `18px 30px 30px` ／ section `4px 26px 26px`・`margin: 34px 0` ／ h1 `14px 20px`・`margin: 26px 0 20px` ／ h2 `6px 12px`・`margin: 30px 0 12px` ／ h3 `padding-bottom: 3px`・`margin: 20px 0 8px` ／ pre `13px 16px` ／ th・td `9px 12px`。section の上 padding を詰めるのは、先頭の h1 が自前の上 margin を持つため。タイトルバー・フッターの左右は本文の `padding: 0 30px` に揃える
- **SVG の表示幅は viewBox で決まる**。`max-width: 100%` は親を超えないための上限で、親が広がっても拡大はしない。折り返し幅を変えても図の寸法は変わらない

## クラス名

html2md が読むクラス名。プロジェクトごとに違う名前を使わない。集計・移行手順・実例は html2md の資料を見る（参照先は「HTML と Markdown の併存」に書いてある）。

| 用途 | クラス名 |
|---|---|
| 章 | `<section class="chNN" id="chNN">` |
| バッジ | `badge` ＋ `b-ok` / `b-ng` / `b-warn` / `b-none` |
| callout | `callout` ＋ `callout-tip` / `callout-important` / `callout-warning` / `callout-caution` |
| 表のラッパー | `tablewrap` |
| セル | `num`（数値列・右寄せ） / `nowrap`（折り返さない） |
| タイトルバー | `titlebar` > `inner` ＋ `lead`（補足） ＋ `date`（日付） |
| 目次 | `toc` |
| Markdown に出さない | `md-skip` |
| 折りたたみを見出しに展開 | `md-flat`（`details`） |
| 課題番号 | `no`（`summary` 内） |
| コードの言語 | `<code class="language-xxx">` |
| 章一覧を表にする | `chapters`（`ul`）＋ `data-columns`（属性・必須）＋ `part`/`ttl`/`desc`（`span`） |

- **バッジの予約語は `b-ok` / `b-ng` / `b-warn` / `b-none` の4つ**。それ以外の `b-*` は種類のラベルとして記号なしの太字になる
- **章の連番は html2md が振る**。HTML 側に番号を書かない（二重になる）
- **コードの言語は正式名で書く**（`powershell` `typescript` `javascript` `csharp` `shell` `batch` `python` `css` `json` `yaml` `sql` `diff` `xml` `html` `markdown`）。略称（`ps1` `ts` `js` `cs` `sh` `cmd` `py` `yml` `md`）も GitHub は認識するが表記を揃える。ハイライト不要は `text`。**`txt` は使わない**（AdBlock のフィルタ構文として解釈される）

## callout の種別

**読み手がその内容を知らずに進むと何が起きるか**で決める。文章の強さや語調では決めない。

| 種別 | 知らずに進むと |
|---|---|
| NOTE | 何も起きない。背景を知らないだけ |
| TIP | 損をする。知っていれば得だった |
| IMPORTANT | 選択を誤る。制約や数値の意味を知らずに決めてしまう |
| WARNING | 損害が出る。ただし取り返しはつく |
| CAUTION | 取り返しがつかない |

- **WARNING と CAUTION の境目は、やり直しの対象がコードかデータかで見る**。コードは書き直せるが、その間に入ったデータは戻らない。データが残るなら CAUTION
- 迷ったら NOTE にする（種別を書かなければ NOTE になる）
- **本文の語で機械的に決めない**。同じ語でも重さが違う

## 作成日・更新日

- 「# ドキュメントの作成日・更新日」を参照する

## root の README.html と資料の html は相互リンクする

- root の `README.html` を作成・更新する際は、参照する資料の html ファイルへリンクを張る
- 資料の html を作成する際は、root の `README.html` へ戻るリンクを本文（`.wrap`）の先頭とフッターの両方に張る（タイトルバーの帯の中には入れない）（フッターに日付等は書かない）
- **root の `README.html` には親サイト（`../`）へ戻るリンクを、本文（`.wrap`）の先頭とフッターの両方に張る**（フッターに日付等は書かない）
- **戻るリンクは上下とも紺のバッジにする**（`--navy1` → `--navy2` の 100deg グラデーション ＋ 白文字）。上下で見た目を変えない。**`border-radius: 6px`**
- **ラベルは `⌂`（家）のアイコンだけにし、文字を付けない**。書き方は「資料間のリンク」のアイコンの項に従う

## README に状態を書かない

適用条件: root の README を作るとき、更新するとき。

1. **進捗・状態を書かない**。「未」「着手」「済」のバッジ、進捗表、「準備中」「次は〜に着手する」を置かない
2. **状態は issues と status に置き、README からはリンクする**（使い分けは「課題の管理」を参照）
3. **README に書くのは変わらないもの**。何であるか・何を目的とするか・何を対象とするか・どこに資料があるか
4. **順序を示す語も状態になる**。「まず〜、後から〜」は対応が済めば古くなる。順序は計画書側

理由: README は最初に読まれるが、更新の手が最も届きにくい。古い状態が残ると、読み手は他の記述も疑う。

## タイトル・見出し
- **ページ最上部のタイトルバーは紺色背景**（大きめの文字で資料タイトルを表示、補足情報は中に小さく白系文字で）。濃い紺色→やや明るめの青への2色グラデーション
- **章見出し(h1)は複数回登場する前提で、虹色(紫・藍・青・緑・黄・橙・赤)を順番に割り当てる**。`--accent`（暗い）→`--accent2`（明るい）の2色グラデーション。**`border-radius: 8px`**
- **章のアクセント色は `.ch01`〜`.ch99`（ゼロ埋め2桁）のクラスに `--accent` / `--accent2` / `--soft` の3変数で定義し、`<section>` と目次の `<li>` の両方に同じクラスを付ける**。h1・h2・thead・pre は `var(--accent)` を参照するだけにする
- **`nth-child` で章を数える書き方は使わない**（章間に区切り要素を入れるとずれる）。**クラス名を1桁にしない**（`ch1` が `ch10` `ch11` に前方一致し、一括置換で壊れる）
- **章見出し(h1)のスタイルは `section h1` にスコープする**。`h1` 単独のセレクタにするとタイトルバー内の h1 にも降りかかり、箱が二重になって上下余白が過大になる
- **タイトルバー内の h1 は `.titlebar h1` として独立に定義する**（font-size・margin・color だけを書く）。`background: none` / `box-shadow: none` のような打ち消しは書かない。打ち消しは章側に装飾を足すたびに追随が必要で、書き忘れで壊れる
- **`--accent` / `--accent2` / `--soft` は `:root` にも既定値を置く**（`--navy1` / `--navy2` / `#f2f5fb`）。章クラスの外に置いた「はじめに」「まとめ」等の h2・pre・table で変数が未定義になり色が消えるのを防ぐ。紺を既定にすると、章に属さない要素がタイトルバー・目次・フッターと同系色に揃う
- h2はそのセクションのアクセントカラーを左ボーダー等で継承
- セクション背景は「アクセントカラーの薄い色 → 白」のグラデーション、テーブルヘッダーは `th` 要素ごとにアクセントカラーのグラデーション（`thead` 全体ではなく列単位で独立してかける）
- **h3 は `border-bottom: 2px dotted var(--accent2)` ＋ `display: inline-block`**（下線を文字幅で止める）。**pre は `border-left: 5px solid var(--accent2)`** でアクセント色を継承する
- **table は `border-radius` ＋ `overflow: hidden`** をセットで指定する（指定しないと thead のグラデーションが角を突き抜ける）。**行は `tr:nth-child(even) td` で `#fafbfe` のゼブラ**にし、`td` は `vertical-align: top` にする
- `background-size`は指定しない（100%を超える値だとグラデーションが要素内で切れて見える）
- 色相(Hue)は280°(紫)から0°(赤)まで減算方向に割り当てる（`hsl()`で指定。紫→青→緑→黄→橙→赤の順に経由する。マゼンタ側の短い経路は使わない）
- **刻み幅は 280 ÷ (章数-1)**。n番目の章の色相は `280 - 刻み幅 × (n-1)`。最初の章が280°、最後の章が0°に着地する。h1が2個以下になる構成では「章(h1)が2個以下の場合」のルールを適用するため、この表は3章から始まる

  | 章数 | 各章の色相 |
  |------|-----------|
  | 3 | 280 / 140 / 0 |
  | 4 | 280 / 186.7 / 93.3 / 0 |
  | 5 | 280 / 210 / 140 / 70 / 0 |
  | 6 | 280 / 224 / 168 / 112 / 56 / 0 |
  | 7 | 280 / 233.3 / 186.7 / 140 / 93.3 / 46.7 / 0 |
  | 8 | 280 / 240 / 200 / 160 / 120 / 80 / 40 / 0 |
  | 9 | 280 / 245 / 210 / 175 / 140 / 105 / 70 / 35 / 0 |

- 彩度・明度は `--accent`: 彩度78%/明度25%、`--accent2`: 彩度58%/明度55%、`--soft`: 彩度28%/明度95%

## SVG図

- **グラデーションの角度は用途で固定する**: タイトルバー `135deg` ／ 横長の帯（h1・thead・目次バッジ・バッジ）`100deg` ／ 上下フェード（section・pre）`180deg` ／ 左右フェード（h2）`90deg`
- **SVG図の箱は下から上に明るくなる縦グラデーションで塗る**。`<linearGradient x1="0" y1="1" x2="0" y2="0">` に 下＝`--accent`（濃い）→ 上＝`--accent2`（明るい）の2ストップを置く。SVGは y=0 が上なので `y1="1"` が下になる
- **`<defs>` 内の id（gradient・marker・clipPath・filter 等）はすべてページ全体で一意にする**（`g-01-3a` のようにファイル番号-図番-連番を含める）。同じidが複数あるとブラウザは文書順で最初の1つだけを使い、他の図が全部その定義を参照してしまう
- **gradient はその章の `<section class="chNN">` の中に書く**。`stop-color="var(--accent)"` は `<stop>` の位置で解決されるため、ページ先頭の共通 defs に置くと `:root` の紺になってしまう
- **箱の中の文字は `fill="#fff"`** にする（下端が明度25%で黒文字が読めないため）
- **複数の対象を並べる比較図は箱ごとに色相を変える**。色相は章と同じ虹色レンジ（280°→0°）から選び、彩度・明度は下 `78%/25%`・上 `58%/55%` に揃える
- **SVGは `viewBox` を必ず付け、`width` 属性は書かずに `max-width: 100%; height: auto;`** で伸縮させる

## 目次

- **目次の各項目は、対応する章と同じアクセントカラーのバッジにする**。`--accent`→`--accent2` のグラデーション＋白文字で、章見出し(h1)と色を一致させる。**`border-radius: 6px`**
- **バッジは固定幅で揃え、文字は左寄せにする**。親の `ol` に `display: flex` ＋ `flex-wrap: wrap` ＋ `gap: 8px`、バッジ自身は `display: -webkit-box` ＋ `-webkit-line-clamp: 2` ＋ `white-space: normal`。**幅は `width: 310px` を初期値とし、必ず `max-width: 100%` を併記する**（狭い画面で親からはみ出さないため）
- **1行+ellipsis で決め打ちにしない**。項目間で文字数の差が大きい（英語混じり等）と文字が欠ける。2行までの折り返しを基本とし、`text-overflow: ellipsis` は3行目以降が出る極端なケースの保険とする
- **番号は CSS カウンタで自動採番する**（`ol` に `counter-reset`、`li` に `counter-increment`、`a::before` に `content: counter(...)`）。項目を増減しても番号を書き直さずに済む
- **バッジの文字は番号も含めて太字にする**（`font-weight: 700`）

## 章を増減したときの色相の振り直し

- **章を追加・削除したら、全章の色相を新しい章数で計算し直す**。目次バッジも同じ値に揃える
- **一括置換するときは、旧値と新値の衝突に注意する**（例: 7→9章では 140 が旧ch4と新ch5の両方に現れる）。一度プレースホルダに置換してから新値に戻す

## はみ出す要素は横スクロールさせる

- **表は overflow-x: auto のラッパーで包む**。pre にも overflow-x: auto を指定する。指定しないと幅の広い表やコードでページ全体が横に伸びる
- **折り返してほしくないセルは個別に white-space: nowrap を当てる**（日付・件数・パス等）。数値列は右寄せにする

## CSS と JS の持ち方は docs/ かどうかで決める

適用条件: HTML を作るとき。

- **`docs/` 配下は共通の外部ファイルにする**。CSS は `docs/css/style.css`、JS は `docs/js/`。複数の資料が「次へ」で連なる公開資料であり、色相やデザインを変えるとき1ファイルを直せば済む
- **`docs/` 以外（`notes/`・root の README 等）は単独の HTML にする**。CSS を `<style>` にすべて書き、外部ファイルを参照しない。**1 ファイルをコピーするだけで同じ見た目になる**
- どちらも **CDN を参照しない**
- `docs/` 配下の HTML に書くのは、その資料だけのもの（章アクセント `.chNN`、目次の資料番号、`counter-reset` / `counter-increment`）
- **`counter-reset` / `counter-increment` は共通 CSS に置かない**。読めなかったときに番号がすべて 0 になる
- **CSS が読めなかったときの代替色を `<link>` の前にインラインで書く**（`docs/` 配下のみ。単独 HTML には不要）

  ```html
  <style>
  /* css/style.css が読めなかったときの代替色 */
  .titlebar, section h1, th, a.doclink, .badge { background: #12224d; color: #fff; }
  </style>
  <link rel="stylesheet" href="css/style.css">
  ```

## 章(h1)が2個以下の場合

- 紺色の**ミニタイトルバー**（タイトルバーと同じ色のグラデーション）を区切りに使い、配下の項目見出しをh1にして連続する虹色を割り当てる（3個以上ならこの構造は不要）

## その他

- グラデーションを多用し、h1(強め)・table(軽め)にbox-shadowを入れて浮かせる。本文はカラフルに、バッジは文中の先頭に置く
- **章に依存しない共通色は `:root` に置く**: `--navy1: #12224d` / `--navy2: #2f5fbf`（タイトルバー） / `--ink: #1c2330`（本文） / `--ink-soft: #4a5568` / `--line: #d9dfe8`（罫線） / `--code-bg: #f4f6fa`。`code` は `background: var(--code-bg)` ＋ `border: 1px solid var(--line)` ＋ `color: #17335f`
- 良い/悪い/未実施/警告はバッジで色分けし、**100deg の2色グラデーション**にする: 良い・完了 `#1d7a3c`→`#45b56c`（緑） / 悪い・リスク `#a51f22`→`#e05a5c`（赤） / 未実施 `#5a6472`→`#97a1ae`（灰） / 警告 `#b8620a`→`#f0a548`（橙）。いずれも `color: #fff`、`white-space: nowrap`
- **警告・注意・落とし穴・補足は `.callout` で囲む**。`border-left: 6px solid var(--accent)` ＋ `--soft`→白の上下グラデーション ＋ `border-radius: 0 8px 8px 0`。中の `strong` は `var(--accent)` にする
- **本文で述べた結論を callout で言い直さない**。callout には本文に無いことだけを書く。消しても本文だけで意味が通るなら、その callout は不要
