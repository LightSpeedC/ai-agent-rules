# セキュリティルール

## 機密情報のマスキング

以下に該当する情報は値をマスクするか出力に含めない（ファイルパス・行番号などの場所情報は出力してよい）:

- **クレデンシャル**（平文のユーザ名・パスワード・APIキー等）
- **実在の個人名・メールアドレス・社名**（ユーザ本人・第三者を問わず）→ `〈個人名〉` `〈メールアドレス〉` `〈社名〉` などの代替表現を使う。**ただし社名がマスク対象になるのは、取引先・顧客・所属先として言及するとき**。調査・比較の対象として公開情報（クラウド事業者名・製品名・サービス名）を書くのは対象外
- **ローカルPC固有情報**（フルパス中のユーザ名部分、ホスト名・マシン名）→ `~` や `<username>` などの代替表現を使う
- **内部ホスト名・プライベートドメイン**（`*.internal`、`*.local`、社内システムのFQDN等）、**認証トークンやセッションIDを含むURL** → `<hostname>` や `<fqdn>` などの代替表現を使う
- **実在の内部ネットワークのIPアドレス**（社内LAN・VPN等の具体的なアドレス帯）→ `<IPアドレス>` などの代替表現を使う。ループバックやドキュメント用アドレス（127.0.0.1、192.0.2.0/24等）は対象外

パブリックな一般サービス（`github.com`、`google.com`等）は通常通り出力してよい。

- **上記はすべて、出力とファイルの両方が対象**。ソースコード・テストデータ・テストスクリプト・課題・計画・すべてのドキュメント・ログに書かない。**AI との応答にも書かない**（会話はAIエージェントのログに残る。例えば JSONL）
- **Git のコミット author は変えない**（公開リポジトリでは実名とメールアドレスが表示される。これは了承済み）。**ただしその値を応答やドキュメントに書かない**。`git log` の結果を示すときも `〈個人名〉 <〈メールアドレス〉>` とマスクする

### フルパスを出さない

適用条件: コマンドを実行するとき、スクリプトを書くとき、応答にパスを書くとき。

- **ユーザプロファイル配下のパスをリテラルで書かない**。`$env:USERPROFILE` や `~` を使う。コマンドの文字列自体も会話ログに残るため、コマンドの中にも書かない
- **スクリプトが表示するパスもユーザ名を伏せる**。`$Path.Replace($env:USERPROFILE, '~')` を通してから表示する。伏せるための道具が漏らす側にまわらないようにする
- **ツールの出力にフルパスが出ても、応答へ引き写さない**。ツールの出力は防げないので、防げるのは応答側だけになる。場所を示す必要があるときはプロジェクトからの相対パスにする
- 対象は自分のホームだけではない。`C:\Users\` 配下はすべて対象
- **ルールのファイル名を書かない**。共通ルールと呼ぶ。応答もチャットも対象。

## .gitignore で除外されたファイルの取り扱い

- **`.gitignore` に指定されているファイル・ディレクトリは原則として読まない**
- それらの内容を参照してコメント・提案・判断を行わない
- 出力に含めない（そもそも読んではいけない）

## プロジェクトフォルダ外へのアクセス

- 読み書き・探索・実行の対象はカレントプロジェクトフォルダ内に限定する。外のフォルダを見る必要が生じたら、対象パスと目的を提示して事前に確認を取る
- ユーザが特定のフォルダへのアクセスを許可した場合は、そのフォルダを対象に加える。許可はセッション内で有効
- **「調査してよい」「見てよい」は読み取りの許可**。書き込み・修正・実行には別に許可を取る
- **意図しない実行も同じ**。対象を渡し損ねたツールが探索範囲を広げ、外のファイルを走らせることがある（「対象を渡すコマンドは、渡ったことを確かめてから実行する」を参照）
- **他プロジェクトのファイルは直さない**。直す必要が見つかったら、何をどう直すかを共通のルール文書に書き、そのプロジェクト側で直してもらう
- 本ルールで用途を明示済みの共有環境（PlayWright・ai-agent-tools・ai-chat-lite）と `~/.claude` 配下は、確認なしで参照してよい
- **ドキュメント・応答から、よそのプロジェクトのファイル・URLへリンクを貼らない**。プロジェクト名を文中に書くのは構わないが、リンク化（`<a href>` / Markdown リンク）はしない。**理由**: リンク先は相手プロジェクトの構成変更で容易に壊れる。また読み手がリンクをたどって別プロジェクトの管理外領域に踏み込む導線を作ってしまう
