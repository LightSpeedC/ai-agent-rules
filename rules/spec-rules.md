# 仕様の書き方と置き場

適用条件: 動作を決めたとき、決めた動作を資料にするとき、他プロジェクトに使い方を見せるとき。

## 3 つの置き場

| 層 | 置き場 | 書くこと | 更新 |
|---|---|---|---|
| 概要仕様 (USAGE) | root の `<名前>-USAGE` | 呼び手が 1 回読めば使える範囲と、外から見える挙動の**結論** | 呼び手に見える変更のたび |
| 詳細仕様 | `notes/50_spec/` | 結論の**根拠と内訳**。内部の動き、全ケース、理由 | 実装のたび。**現在の姿が正** |
| 計画 | `notes/10_plan/` | 当時の考え | **書き換えない** |

## 何をどちらに書くか

適用条件: 仕様を書くとき。

- **読み手で分ける**。USAGE は他プロジェクト (呼び手)、詳細仕様は作る側
- **粒度で分ける**。USAGE は概要、詳細仕様は詳細
- **境目の基準は「知らないと呼び手が誤るか」**。誤るなら、結論を USAGE に書く。実装を変えても呼び手に見えないなら、詳細仕様に書く
- **結論は USAGE、根拠と内訳は詳細仕様**。同じ事実を両方に書かない。詳細仕様は USAGE の見出し名で指す
- **呼び手が詳細仕様を読まなくても使えるようにする**。詳細を読まないと誤る事柄は、結論を USAGE に書く

## 概要仕様 (USAGE)

適用条件: 他プロジェクトから呼ばれる道具・サービスを持つプロジェクト。

- **置き場は root の `<名前>-USAGE.html`**。Markdown は html2md が生成する。`docs/` (外部に配る資料) とは別
- **他プロジェクトのルール・資料は、USAGE を見出し名で指す**。詳細仕様を指さない
- **書くのは、呼び方・主なオプション・終了コード・落とし穴・出力の形**

## 詳細仕様 (50_spec)

適用条件: 動作を決めたとき。

- **話題ごとに 1 ファイル**。番号は付けない。並び順を決めたいときは、ローカルルールに書いて番号を付けてよい
- **現在の姿を書く**。変わったら書き換える。履歴は残さず、経緯は計画へのリンクで示す
- **全体像を示す 1 ファイルを置く**。大きな変更の設計書は、これに当たる
- **実装と食い違ったら、実装が正**。詳細仕様を直す

## 計画との関係

適用条件: 計画を書くとき、実装を終えたとき。

- **計画は当時の記録。本文を書き換えない**。足してよいのは、実装後の結果だけ
- **仕様を変えるときは、新しい計画を立てる**。古い計画を改訂しない
- **仕様が決まったら、同じ回のうちに詳細仕様 (と、呼び手に見えるなら USAGE) に書く**。実装の結果を反映する回が引き金
- **リンクは詳細仕様から計画へ張る**。計画から詳細仕様へは張らない (計画を書き換えないため)
- **導入は今後の分から**。既存の計画は動かさない
