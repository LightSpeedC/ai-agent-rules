# DB 定義のルール

適用条件: DB（SQLite 等）のテーブル・列・索引を定義・変更するとき。

## 日時

- **JST の `yyyy/mm/dd hh:mm:ss.ccc`、固定 23 文字の TEXT にする**。`CHECK (length(列) = 23)` を付ける
- **列名の語尾は `_at`**
- **理由**: 固定長なので、文字列の辞書順がそのまま時系列順になる。DB を直接見ても読める。形が混ざると比較が壊れる（区切りを `-` から `/` に揃え直した実例がある）
- **プログラムの中の計算は、ミリ秒の数値でよい**。DB に書く・読むところだけで変換する
- 書式は「アプリケーションログの日時形式」と同じ

## 名前

- **主キーは `<テーブル名>_id`**（`id` だけにしない）。連番は `_seq`
- **外部キーの列名は、参照先の主キーと同じ名前にする**
- **略語を使わない**。単体で読んで意味が取れる名前にする。業界の用語として通じるもの（`pid` 等）を許すときは、そのプロジェクトで決めて、定義の先頭に書く
- **型名と同じ名前を避ける**（`text` → `<対象>_body`）。DDL が `text TEXT` になって読みにくい
- **真偽値は `is_` で始め、`INTEGER` に `CHECK (列 IN (0, 1))` を付ける**。SQLite に真偽値の型は無い
- **サイズ・時間の単位は、列名の語尾（`_bytes`・`_ms`）か、定義の先頭のコメントで示す**。1 つのプロジェクトの中で、どちらかに揃える
- **索引の名前は `<テーブル名>_ix_<列名>_<列名>`**。名前順に並べると、テーブルごとにまとまる
- **テーブル名の単数・複数は、プロジェクトの中で揃える**

## 値が取れなかったとき

- **NULL にする。0 や空文字で埋めない**。0 は「使っていない」「暇だった」と読まれ、平均や合計を狂わせる。実例: 権限が無くて読めなかったプロセスのメモリが 0 で返ってきた
- **NULL を許す列には、なぜ NULL になるかを、コメントに書く**
- **結合は `LEFT JOIN` にする**。内部結合は、NULL の行を黙って落とす

## 制約

- **SQLite では `STRICT` を付ける**。型を守らせる
- **長さと、取りうる値は、`CHECK` で縛る**。範囲外の値が入らないようにする

## 版管理

- **SQL は、版ごとのフォルダ（`ver_000001/`）に置く**。`versions` テーブルに、どこまで当てたかと、当てた SQL の指紋（SHA-256）を持つ
- **当て済みの SQL を書き換えない**。当て済みの環境では二度と実行されず、環境ごとに形が違う状態になる。変更は、新しい版として足す。**SQL の先頭に、そう書く**
- **番号は連続させる**。飛んでいたら止める
- **1 つの版を 1 つのトランザクションで当て**、失敗したら巻き戻して、起動を失敗させる
- **下りは持たない**。版を上げる前に、控えを取る
- **まだ誰にも当てていない版は、書き換えてよい**（導入の前。当てたあとは、上の決まりが効く）
- **SQL には、なぜそうしたかを書く**。あとから読んで、順路を辿れるようにする
