# 記録と運用

## セッション制限報告時の確認

適用条件: 利用者からセッション制限・レート制限で止まったと報告されたとき。

- **自分の会話ログ（JSONL）から `rate_limit`・`apiErrorStatus` を検索して確かめる**。置き場は `~/.claude/projects/<プロジェクト>/<セッションID>.jsonl`

## セッションログの自動保存

- **会話ログ（JSONL）は、各プロジェクト直下の `etc/history/jsonl/` に自動でコピーされる**。そのプロジェクトの全セッションが対象
- 仕組みは `~/.claude/settings.json` の `hooks`（SessionStart・Stop）。実体は ai-agent-rules プロジェクトの `tools/80_ops/claude-hooks/`

## cron はセッションの中だけで生きる

適用条件: `CronCreate` で定期実行を仕込むとき。

- **ディスクに書かれない**。セッションを閉じれば消え、`--resume`／`--continue` でも戻らない
- **7 日で自動失効する**
- **作り直すのは、ローカルルールに定義があるものだけ**。開き直したとき・失効したときに、指示を待たずに作り直す。ほかは無指示で作り直さない

## セッションを開き直したとき

- **chat待受け・cron は前セッションの分が切れている。指示を待たずに張り直す**
  - cron: 「cron はセッションの中だけで生きる」に従う
  - chat待受け: 前回のセッションで張っていたもの（会話に `aichat wait` の起動がある）。新規のセッションでは張らない
- **値（頻度・prompt・ID・ルーム）は、ローカルルールか前回の起動に従う**

## 手順は 1 箇所に置く

適用条件: 手順や値を書くとき（計画書・README・cron やワークフローの指示文）。

- **同じ手順を 2 箇所に書かない**。片方だけ直せば、もう片方が古いまま残る
- **値（時刻・cron の式・件数・バージョン等）も 1 箇所に置く**。ほかの資料からは、置き場を見出し名かリンクで指す。例に値を書くときは、書式（`月/日 時:分`）にする
- **無人実行（cron・ワークフロー・フック）の指示文に手順を写さない**。資料を毎回読ませる形にする。資料を直せば次の発火から新しい手順になる
- **共通ルールの本文をプロジェクト資料に写さない**。見出し名で参照する
- **手順を変えたら、写しを持つ側を点検する**。動いている cron・プロジェクト資料・周知済みの文面
- **食い違いの扱いは「ローカルルール（プロジェクトルール）」に従う**

## その場で受けた決めごとは、その回のうちに書く

適用条件: 作業中に利用者から手順を指示されたとき。

- **繰り返し使う手順なら、同じ回のうちにプロジェクト資料（計画書・README）へ書く**。今回限りの事実は書かない
- **ルール文書（共通ルール・ローカルルール）への反映は指示を待つ**（「ルールの更新タイミング」に従う）
- **決めごとには引き金を書く**。何を書くかだけを決めても、いつ書くかが無ければ実行されない

## ルールの更新タイミング

適用条件: 共通ルール・ローカルルールのいずれかを書き換えるとき。

- **文言を提示し、実行語（「重大な操作の確認方法」）で指示されてから書き込む**。提示済みの文言に「反映して」と指示されたら、再確認せず直ちに書き込む
- **試している段階では、良い結果が出てもルールを書き換えない**。変えるのは実験対象のファイル（HTML 等）だけ

## 共通ルールを変えたら周知する

適用条件: 共通ルールを書き換えたとき。体裁だけの変更とローカルルールは除く。

- **反映した直後の応答で、周知案を続けて提示する**。別の応答に分けない
- **未送信の周知案があれば、そこへ合流させて 1 回にまとめる**。送信済みなら別便にする
- **周知先は `public` ルーム**。`say` はルームを 1 つしか取らない
- 書き方と、送る前の確認は「ai-chat-lite（AI 間チャット）の利用」に従う

## フィードバックの記録先

適用条件: 進め方について利用者から指摘を受けたとき。

- **進め方への指摘は、自動 memory ではなく共通ルールに記録する**。書き込む時期は「ルールの更新タイミング」に従う

## Claude Code への不具合報告（/feedback）

適用条件: 利用者が Claude Code に feedback したいと言ったとき（`/feedback` の実行も含む）。

- **確認を取らずに、SendFeedback で下書きをキューに入れる**。1 件ずつ別の下書きにする。送るのは利用者が `/feedback` で承認したときだけ
- **入れた下書きの内容を、応答に書く**。ツールは「知らせない」よう案内するが、利用者が内容を確かめるため、こちらを優先する
