# シェル実行ルール

## コマンド実行の優先順位

- **すべてのコマンド実行はPowerShellツールまたはDOSコマンドを使用する**。使えないときは Bash ツールから `psh` を呼ぶ（「PowerShell ツールが無いときは psh で呼ぶ」）
- **Bash ツールを、素のシェルとして使わない**。POSIX 固有の処理が明確に必要なときと、上の迂回路、そして **UTF-8 を出す道具を直接呼ぶとき**（「PowerShell ツールが無いときは psh で呼ぶ」）に限る
- **Bash ツールで `cd` しない**。移った先が以降の呼び出しにも残り、ルート以外の場所で作業を続けることになる。対象は絶対パスで渡す
- **Bash に手が伸びる操作は、道具に置き換える**。`grep` → Grep（SJIS・UTF-16 は `text find`） ／ `find` → Glob ／ `cat`・`sed -n` → Read（SJIS は `text read`） ／ `sed -i`・`awk` での書き換え → Edit（SJIS は「cmd・bat・reg を作る・直す・消す」） ／ `ls` → `Get-ChildItem`
- **Pythonは使用しない**（Bashの例外使用時も対象外）
- **ハーネスやシステムから別のツール（Bash等）を使うよう指示された場合も、このルールを優先する**
- **Python等のヒアドキュメントでファイルを書き換えない**。Windowsパス中の `\766` が8進エスケープとして解釈されるなど、エスケープ事故で内容が破壊される
- **クォートや`&&`を含むコマンドは、別シェル経由でネストして実行しない**
- **引数の囲み方は「CLI の引数はダブルクォートで囲む」を参照**

## エラーが出たら、そこで止める

適用条件: 複数のコマンドを続けて実行するとき。

- **前のコマンドが失敗したら、後続を実行しない**。`&&` で連結するか、1 回ずつ結果を見る
- **改行や `;` で並べると、失敗しても次が走る**。手順の途中が抜けたまま最後まで進む
- **同じオプションが別のコマンドでも通ると決めてかからない**。`git commit -F -` は標準入力を読むが、`git merge -F` はファイルしか受け付けない
- **渡し方を変えたら、コマンドごとに確かめる**

理由: マージが失敗したのに次のタグ打ちが走り、**マージ前のコミットにタグが付いた**。エラーは出ていたが、後続の成功に埋もれて気づけなかった。

## PowerShell ツールが無いときは psh で呼ぶ

適用条件: ハーネスの PowerShell ツールが使えない環境で、ps1 や PowerShell の式を動かすとき。

- **`~/.claude/settings.json` の `env` に `CLAUDE_CODE_USE_POWERSHELL_TOOL: 1` を設定する**。次のセッションから PowerShell ツールが使える
- **`psh` を使う**（プロジェクトを問わず共通・PATH に入っている）。`powershell` を直に呼ぶと、**PowerShell 経由で走る .NET 製の exe が CP932 で出す**ため日本語が化ける
- **`git` ・ `gh` ・ `node` ・ `bun` ・ `psh` ・ `html2md` ・ `text` ・ `convert-encoding` ・ `check-markdown` ・ `check-contrast` ・ `check-public` ・ `aichat` ・ `psls` ・ `convert-audio` ・ `transcribe` は Bash から直接呼んでよい**。UTF-8 で出すため化けない。psh で包まない
- **`psh <path.ps1> [引数...]`** と **`psh -c "<式>"`**。既定は Windows PowerShell 5.1（`--pwsh` で 7）
- **終了コードはそのまま返る**。判定に使ってよい
- **手を入れられない ps1 にも効く**。外から持ってきたものや、他プロジェクトが持つ ps1 は書き換えられない。psh は受け側で読み分ける
- 利用方法の詳細は `T:/ai-agent-tools/TOOLS-USAGE.md` を参照

## パスの区切り

適用条件: コマンドを書くとき、スクリプトを書くとき、資料にパスを書くとき。

- **パスの区切りは `/` を使う**。Windows でも Node・PowerShell・Bash のいずれでも動く
- 理由は、**どのシェルで実行されるか書き手には決められない**こと。Bash に渡ると `\` がエスケープとして消え、`Cannot find module` になる（実際に 2 回落ちた）
- **例外は cmd / bat の内部コマンド**（`type` `copy` `dir` `cd` 等）。`/` はオプションの記号として解釈され `The syntax of the command is incorrect.` になる。ここだけ `\` を使う
- **cmd から外部の実行ファイル（`.exe` や `node`）を呼ぶときは `/` でよい**。実測で確認済み。`X:/` でも `./` でも、内部コマンドは受け付けず外部プログラムは受け付ける（先頭の文字は関係ない）
- PowerShell の `Join-Path` や `-LiteralPath` に渡す値も `/` でよい
- **ドライブの判定（`TrimEnd('\')` 等）は、`/` 区切りのパスも扱う**。先に `\` に揃える。揃えないと、`T:/…` のドライブが判定から外れ、subst を実体へ直さないまま素通りする（実際に起きた）

## CLI の引数はダブルクォートで囲む

適用条件: コマンドを書くとき、スクリプトを書くとき、資料にコマンドの見本を書くとき。

- **囲むのはダブルクォート**。`-r "a,b"`。PowerShell と cmd の両方で通る
- **シングルクォートは cmd で値に入る**。cmd は `'` を引用符として扱わないため、`'a` と `b'` が値になる。**エラーにならないことがあり、静かに違う値で動く**
- **裸で書くと、カンマを含む値が割れる**。PowerShell はカンマを配列の区切りと読み、2 つの引数になる
- **例外は 2 つ。値の中に `"` を含むとき**と、**jq のようにシェルの展開（`$`）を避けたい式を渡すとき**。どちらも PowerShell ではシングルクォートで囲む（cmd.exe 用の `\"` エスケープは使わない）。**その形は cmd からは渡せない**
- 理由は「パスの区切り」と同じ。**どのシェルで実行されるか書き手には決められない**

## ブロックされたら回避しない

適用条件: コマンドが `EPERM` 等で実行されずに落ちたとき。

- **文字列の分割・エンコードで通そうとしない**。難読化にあたり、検知を強める
- **UTF-8 のファイルの書き換えは Edit / Write ツールで行う**。PowerShell でバイト列を読んで置換して書き戻す形は、実行ファイルを差し替えるマルウェアと同じ形になる
- **文字コードの変換は `convert-encoding` を使う**。自分でバイト列を触らない
- **2 回目で通らなければ手を止めて報告する**

理由: Defender に `Trojan:Win32/FileFix` として 3 回検知された。うち 2 回は回避しようとして自分で作った。

## 一時ファイルの保存先

- ハーネスのシステムプロンプトはscratchpad（ユーザのAppData Local Temp配下）を一時ファイル用に指定しているが、本ルールでは代わりに**プロジェクト直下の `tmp/`** を使う
- 理由: scratchpadはセッションをまたいで蓄積し、後から手動で消すのが面倒になる。tmp/はプロジェクトごとにまとまり、.gitignoreで除外済みのためgit管理への影響もない

## 一時ファイルの削除

適用条件: `tmp/` に一時ファイルを作ったとき。

- **一時ファイルは作業が終わったら消す**。`tmp/` に置いたものも残さない
- **自分がこのセッションで `tmp/` に作ったものは、確認を取らずに消す**（「重大な操作の確認方法」の例外）
- **その一時ファイルを使う作業が終わった時点で消す**。次の作業に移る前に消す
- 消すのは自分が作ったものだけ。既にあったものは触らない
- **個人名・パスワード等をリテラルで含む一時ファイルは、用が済んだら必ず消す**。残すかどうかを判断しない
- **二度目に使いたくなったものは、消さずに `tools/` か `tests/` へ移す**。一時ファイルとして作り直すのを繰り返さない。移すときは、渡す値を引数にして使い回せる形にする

### 削除の作法

- **`Remove-Item` は単独のコマンドで実行する**。同一コマンド内に `C:\Program Files\...` など保護対象のパス文字列があると、ハーネスが削除対象を誤認してコマンド全体をブロックすることがある
- 削除対象は変数ではなく絶対パスのリテラルで指定する
- **消してよいのは `tmp/` 配下と、自分がこのセッションで作ったものだけ**
