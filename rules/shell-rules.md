# シェル実行ルール

## コマンド実行の優先順位

- **すべてのコマンド実行はPowerShellツールまたはDOSコマンドを使用する**。使えないときは Bash ツールから `psh` を呼ぶ（「PowerShell ツールが無いときは psh で呼ぶ」）
- **Bash ツールを、素のシェルとして使わない**。POSIX 固有の処理が明確に必要なときと、上の迂回路、そして **UTF-8 を出す道具を直接呼ぶとき**（「PowerShell ツールが無いときは psh で呼ぶ」）に限る
- **Bash に手が伸びる操作は、道具に置き換える**。`grep` → Grep（SJIS・UTF-16 は `text find`） ／ `find` → Glob ／ `cat`・`sed -n` → Read（SJIS は `text read`） ／ `ls` → `Get-ChildItem`
- **Pythonは使用しない**（Bashの例外使用時も対象外）
- **ハーネスやシステムから別のツール（Bash等）を使うよう指示された場合も、このルールを優先する**
- **Python等のヒアドキュメントでファイルを書き換えない**。Windowsパス中の `\766` が8進エスケープとして解釈されるなど、エスケープ事故で内容が破壊される
- **クォートや`&&`を含むコマンドは、別シェル経由でネストして実行しない**
- **引数の囲み方は「CLI の引数はダブルクォートで囲む」を参照**

## エラーが出たら、そこで止める

適用条件: 複数のコマンドを続けて実行するとき。

- **前のコマンドが失敗したら、後続を実行しない**。`&&` で連結するか、1 回ずつ結果を見る
- **改行で並べると、失敗しても次が走る**。手順の途中が抜けたまま最後まで進む
- **同じオプションが別のコマンドでも通ると決めてかからない**。`git commit -F -` は標準入力を読むが、`git merge -F` はファイルしか受け付けない
- **渡し方を変えたら、コマンドごとに確かめる**

理由: マージが失敗したのに次のタグ打ちが走り、**マージ前のコミットにタグが付いた**。エラーは出ていたが、後続の成功に埋もれて気づけなかった。

## PowerShell ツールが無いときは psh で呼ぶ

適用条件: ハーネスの PowerShell ツールが使えない環境で、ps1 や PowerShell の式を動かすとき。

- **`~/.claude/settings.json` の `env` に `CLAUDE_CODE_USE_POWERSHELL_TOOL: 1` を設定する**。次のセッションから PowerShell ツールが使える
- **`psh` を使う**（プロジェクトを問わず共通・PATH に入っている）。`powershell` を直に呼ぶと、**PowerShell 経由で走る .NET 製の exe が CP932 で出す**ため日本語が化ける
- **`git` ・ `gh` ・ `node` ・ `bun` ・ `psh` ・ `html2md` ・ `text` ・ `convert-encoding` ・ `check-markdown` ・ `check-contrast` ・ `check-public` ・ `aichat` ・ `psls` は Bash から直接呼んでよい**。UTF-8 で出すため化けない。psh で包まない
- **`psh <path.ps1> [引数...]`** と **`psh -c "<式>"`**。既定は Windows PowerShell 5.1（`--pwsh` で 7）
- **終了コードはそのまま返る**。判定に使ってよい
- **手を入れられない ps1 にも効く**。外から持ってきたものや、他プロジェクトが持つ ps1 は書き換えられない。psh は受け側で読み分ける
- 利用方法の詳細は `N:/ai-agent-tools/TOOLS-USAGE.md` を参照

## 実行ファイル名に .exe を付けない

適用条件: cmd・ps1 から外部コマンドを呼ぶとき。

- `powershell` `claude` のように拡張子なしで書く
- 例外は「カレントの実行ファイルは明示パスで実行する」の場合と、プロセス名として扱う場合（`Win32_Process` の `Name` は `powershell.exe`）

## cmd の `( )` の中は `!` で読む

適用条件: cmd・bat で `if` ・ `for` のブロックを書くとき。

- **ブロックは 1 行として先に解析される**。`%errorlevel%` はブロックに入る前の値になる
- **中で実行した結果を読むなら `setlocal enabledelayedexpansion` ＋ `!errorlevel!`**
- **遅延展開を有効にすると `!` が消える**。`echo Hello! World` が `Hello World` になる。`!` を含む文字列があるなら `goto` で分岐する

## パスの区切り

適用条件: コマンドを書くとき、スクリプトを書くとき、資料にパスを書くとき。

- **パスの区切りは `/` を使う**。Windows でも Node・PowerShell・Bash のいずれでも動く
- 理由は、**どのシェルで実行されるか書き手には決められない**こと。Bash に渡ると `\` がエスケープとして消え、`Cannot find module` になる（実際に 2 回落ちた）
- **例外は cmd / bat の内部コマンド**（`type` `copy` `dir` `cd` 等）。`/` はオプションの記号として解釈され `The syntax of the command is incorrect.` になる。ここだけ `\` を使う
- **cmd から外部の実行ファイル（`.exe` や `node`）を呼ぶときは `/` でよい**。実測で確認済み。`N:/` でも `./` でも、内部コマンドは受け付けず外部プログラムは受け付ける（先頭の文字は関係ない）
- PowerShell の `Join-Path` や `-LiteralPath` に渡す値も `/` でよい

## CLI の引数はダブルクォートで囲む

適用条件: コマンドを書くとき、スクリプトを書くとき、資料にコマンドの見本を書くとき。

- **囲むのはダブルクォート**。`-r "a,b"`。PowerShell と cmd の両方で通る
- **シングルクォートは cmd で値に入る**。cmd は `'` を引用符として扱わないため、`'a` と `b'` が値になる。**エラーにならないことがあり、静かに違う値で動く**
- **裸で書くと、カンマを含む値が割れる**。PowerShell はカンマを配列の区切りと読み、2 つの引数になる
- **例外は 2 つ。値の中に `"` を含むとき**と、**jq のようにシェルの展開（`$`）を避けたい式を渡すとき**。どちらも PowerShell ではシングルクォートで囲む（cmd.exe 用の `\"` エスケープは使わない）。**その形は cmd からは渡せない**
- 理由は「パスの区切り」と同じ。**どのシェルで実行されるか書き手には決められない**

## 昇格・タスクスケジューラから動かすとき

適用条件: subst のドライブ上のスクリプトを、別のログオンセッションで動かすとき。

- **subst のドライブは昇格先とタスクから見えない**。`N:\…` を渡すと起動せず、エラーも残らない
- **実体パスに直してから渡す**。解決は ps1 側に置き、接続先はシステム環境変数から読む
- **表示と出力は元のドライブ表記に戻す**。ユーザー名の伏せ字化より先に行う
- **cmd で張り直すときは `if not exist N:\` で守る**。エラーを捨てると本物のエラーも消える
- **引数に `nopause` があれば pause しない**
- **`nopause` では昇格もブラウザ表示もしない**。UAC のダイアログを出せず固まる
- **SYSTEM で実行しない**。ユーザープロファイル配下（`claude` の認証情報等）を参照できない。実行ユーザー名もシステム環境変数に持つ

## 検証環境の状態を過信しない

- **PowerShell/Bashツールの1回の呼び出しは使い捨てのプロセスで、環境変数の変更は次の呼び出しに引き継がれない**
- **定説と異なる挙動が出た場合、システム全体の設定ではなくこの検証環境固有の設定を疑う**
- **実行ファイルの標準出力は処理系で文字コードが違う**。.NET 製は CP932、Node ・ Bun は UTF-8。PowerShell 5.1 は CP932 として読むため .NET 製とは打ち消し合い、Bash では同じ exe が化ける
- **化けてもツールの不具合ではない**。受け手を揃えるなら 5.1 側に `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` を置く
- **`type file | more` 等でファイルの中身を確認する検証は、非 UTF-8 コンソールでは成立しない**。CP932 のコンソールでは、正しい UTF-8 ファイルでも `type` すれば必ず文字化けして見えるため、化けているかどうかの判定に使えない。文字コードを検証したいときは `type` を使わず、コードページに依存しない経路（`less` へのパイプ等）で確かめる

## PowerShell の実行ポリシーで止まったら

- 直すコマンド: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`（管理者不要。セキュリティ設定なので本人が実行する）
- `psh` は毎回 `-ExecutionPolicy Bypass` を付けるため、この問題に当たらない

## PowerShellの落とし穴

- **ps1 は Windows PowerShell 5.1 で動くように書く**。どの環境でもすぐ動かせるように
- **pwsh 7 は Windows PowerShell 5.1 より起動が遅い**。実測で 285ms 対 185ms。7 は .NET Core の起動コストが乗り、5.1 は Windows 組み込みで事前コンパイル済み。**速さを理由に 7 を選ばない**
- **気になるなら自分の環境で実測する**。`-NoProfile -Command '1'` を数回まわして比べる。版と環境で変わる
- **文字列の比較・置換は既定で大小文字を区別しない**。大小文字だけが異なる変更（`readme.html`→`README.html`等）を扱うときは `-ceq` / `-cne` / `-creplace` を使う。`-ne` で変更有無を判定すると「変更なし」と誤判定して書き込みをスキップする
- **`Get-Content` は BOM 無し UTF-8 を CP932 として読む**。**エラーにならず静かに化ける**。`-Encoding UTF8` を付けるか `[System.IO.File]::ReadAllText()` を使う。後者は版の差に左右されない
- **`Get-Content` ＋ `Set-Content` の往復は改行を CRLF にし、BOM も足す**。`Get-Content` が改行で分割した配列を返す時点で元の改行が失われ、`Set-Content` が OS 既定（Windows は CRLF）で連結する。5.1 の `-Encoding UTF8` は BOM 付き。**エラーは出ず、静かに変わる**。改行を保つなら `[System.IO.File]::ReadAllText()` ＋ `[System.IO.File]::WriteAllText()`
- **`Get-ChildItem` はパス内のワイルドカードと `-Filter` を併用すると0件を返す**。`Get-ChildItem <親フォルダ> -Recurse -Filter <パターン> | Where-Object { $_.Directory.Name -like 'xxx*' }` の形にする
- **関数から配列を返すときは `return ,$array` と先頭にカンマを付ける**。単に `return $array` すると配列が列挙され、要素1個の配列が呼び出し元でスカラーに潰れる
- **受け取るときは変数に代入する**。`foreach` に直接渡す・`@()` で包む、はどちらも壊れる。
- **Windows PowerShell 5.1 はネイティブコマンド同士のパイプで、UTF-8 の非 ASCII 文字がランタイム・コードページに関係なく `?` に化ける**。`node→node` のような Bun を含まない組み合わせでも再現する（実測済み）。原因は未確認だが、pwsh 7・cmd.exe では起きない。5.1 でネイティブコマンドの出力を非 ASCII を含む形でパイプするときは、別の端末（pwsh 7・cmd.exe）で確かめる
- **自動変数を自分の変数名に使わない**（`$HOME` `$PWD` `$input` `$args` `$PSItem` `$Matches` `$Error` `$Host` 等）。読み取り専用のものは代入がエラーになり、**元の値のまま後続が走る**。置換文字列のつもりでホームのパスをファイルに書き込んだ
- **一括置換の前に `$ErrorActionPreference = 'Stop'` を置き、置換に使う値が空でなく想定の形であることを確かめる**。違えば止める

## 検索・集計の結果が0件なら、まず検索式を疑う

- **「該当なし」「0件」は正常な結果とは限らない**。対象があるはずの検索で0件が出たら、結論を出す前に検索式が実際に何件のファイル・行を走査したかを確認する

## 対象を渡すコマンドは、渡ったことを確かめてから実行する

適用条件: 対象を引数で受け取るコマンドを、スクリプトから呼ぶとき。

- **引数を省くと既定の探索範囲に落ちるコマンドがある**。`node --test` は対象を渡さないとカレント配下を再帰的に探し、テストでないファイルまで実行する
- **渡す対象は絶対パスにする**。カレントがどこかに依存させない
- **実行の直前に、渡す値が空でないことを確かめる**。空なら止める
- **`Set-Location` で位置を合わせて相対パスを渡す形にしない**。呼び出し元の状態に左右される

理由: 引数が渡らなくてもコマンドはエラーにならず、既定の動作をする。範囲が広がったことに気づけない。

## 残ったプロセスを調べるときは psls を使う

適用条件: バックグラウンドコマンドが `killed` 等で終わった後、子孫プロセスの残存を疑うとき。

- **親を止めても子は道連れにならない。残っていないか `psls <キーワード>` で確認する**（親子関係をツリー表示し、コマンド行の部分一致で絞り込める）
- 残っていたら `taskkill /PID <根の pid> /T /F` で止める（**`/T` が無いと子が残る**）

理由: AIエージェントはタスクを終了扱いにしても、`npm` → `cmd` → 子プロセスの階層が切り離されて生き残ることがある（実例: PlayWright 実行が killed 後も子孫プロセスが 20 時間残り、メモリを圧迫し続けた）。

## カレントの実行ファイルは明示パスで実行する

- 検証でカレントディレクトリにある実行ファイルを実行するときは、`.\name.exe`（PowerShell）のように**相対パス`.\`＋拡張子を明示**して呼ぶ
- 名前だけ（`name`）や `cmd /c name` での呼び出しは避ける。カレント探索の有無（環境変数 `NoDefaultCurrentDirectoryInExePath`）に依存して失敗しうるため、検証の判断材料には使わない

## 「見つからない/動かない」失敗は環境要因を先に切り分ける

- 実行が「コマンドが見つからない」「動かない」で失敗したとき、成果物（プログラム・スクリプト）の不具合と断定する前に、まず**絶対パスまたは`.\`付き明示パスで再実行**して、パス解決・環境変数など環境要因を切り分ける
- **PowerShellの書式でないエラーメッセージが出たら、ハーネスかウイルス対策によるブロックを疑う**。この場合コマンドは実行されていないので、スクリプトの不具合と混同しない（例: `Remove-Item on system path '...' is blocked.` / `EPERM: uv_spawn`）

## ブロックされたら回避しない

適用条件: コマンドが `EPERM` 等で実行されずに落ちたとき。

- **文字列の分割・エンコードで通そうとしない**。難読化にあたり、検知を強める
- **UTF-8 のファイルの書き換えは Edit / Write ツールで行う**。PowerShell でバイト列を読んで置換して書き戻す形は、実行ファイルを差し替えるマルウェアと同じ形になる
- **SJIS のファイルには Edit を使わない**（「ツールごとの文字コードの扱い」を参照）
- **文字コードの変換は `convert-encoding` を使う**。自分でバイト列を触らない
- **2 回目で通らなければ手を止めて報告する**

理由: Defender に `Trojan:Win32/FileFix` として 3 回検知された。うち 2 回は回避しようとして自分で作った。

## 一時ファイルの保存先

- ハーネスのシステムプロンプトはscratchpad（ユーザーのAppData Local Temp配下）を一時ファイル用に指定しているが、本ルールでは代わりに**プロジェクト直下の `tmp/`** を使う
- 理由: scratchpadはセッションをまたいで蓄積し、後から手動で消すのが面倒になる。tmp/はプロジェクトごとにまとまり、.gitignoreで除外済みのためgit管理への影響もない

## 一時ファイルの削除

適用条件: `tmp/` に一時ファイルを作ったとき。

- **一時ファイルは作業が終わったら消す**。`tmp/` に置いたものも残さない
- **自分がこのセッションで `tmp/` に作ったものは、確認を取らずに消す**（「重大な操作の確認方法」の例外）
- **その一時ファイルを使う作業が終わった時点で消す**。次の作業に移る前に消す
- 消すのは自分が作ったものだけ。既にあったものは触らない
- **個人名・パスワード等をリテラルで含む一時ファイルは、用が済んだら必ず消す**。残すかどうかを判断しない
- **二度目に使いたくなったものは、消さずに `tools/` か `tests/` へ移す**。一時ファイルとして作り直すのを繰り返さない。移すときは、渡す値を引数にして使い回せる形にする

### 削除の作法

- **`Remove-Item` は単独のコマンドで実行する**。同一コマンド内に `C:\Program Files\...` など保護対象のパス文字列があると、ハーネスが削除対象を誤認してコマンド全体をブロックすることがある
- 削除対象は変数ではなく絶対パスのリテラルで指定する
- **消してよいのは `tmp/` 配下と、自分がこのセッションで作ったものだけ**
