11/07 に利用者の指摘で分かった。環境は 3 種類あり、やり方が違う: (1) 他の Windows PC、(2) 作り直されない Linux の VM (OCI に作り、手で起動する。20261011-claude-code-setup が手で用意した)、(3) セッションごとに作り直されるクラウドのコンテナ (Claude Code on the web)。いまは、この PC で手で用意したものだけが動いている。他の PC では、ホームの CLAUDE.md が参照する `T:/ai-agent-rules/` の clone と `T:` が無く、ルールも読まれない。クラウドでは、入り口 (`tools/10_setup/` と `.claude/settings.json` の SessionStart) のあるプロジェクトだけ `cloud-session-start` が `../ai-agent-rules/` を clone する。新しいプロジェクトには入り口が無い。入り口があっても、AGENTS.md の `@../ai-agent-rules/` の読み込みと、SessionStart の clone のどちらが先かは確かめていない。skill (`~/.claude/skills` へのリンク) とフック (`settings.json` の hooks) は、どちらの環境にも入らない。i261105-01 の「skill とフックを入れる道具」をここへ移した (3-A)。

**やること**

- [着手] クラウドで、AGENTS.md の `@` 参照の読み込みと SessionStart の clone のどちらが先かを、作り直したばかりのコンテナで確かめる。まず 20261011-claude-code-setup (OCI の VM) のセッションに、分かっていることを尋ねた (2-A、11/07)。返事: そちらは作り直されない VM で、事前に clone してホームの CLAUDE.md から読むため、順序は確かめていない。推測では、`@` はセッションの開始時に組み立てられ、SessionStart で clone した分は次のセッションから効く。実機で確かめる必要がある (試験用のリポジトリを作る 1-B)。VM の手順は、そちらの `notes/01_research/r261012-01-クラウド環境の初期手順.html` にある (clone を並べる・ホームの CLAUDE.md に `@` 1 行・PATH は末尾に足す・フックは `settings.json` に手で書いた・skill は入れていない)。0000-work (クラウド) にも尋ね、返事を受けた (11/07): プロジェクトの外を指す `@../ai-agent-rules/common-rules.md` は、clone 済みのコンテナで再開したときも、一度も展開されなかった (プロジェクト内の `@notes/90_rules/local-rules.md` は毎回展開される)。順序ではなく、プロジェクトの外の `@` が読まれないのが原因の見込み (確かめていない)。いまは AGENTS.md のコメントに従い、共通ルールを手で読んでいる。`~/.claude/settings.json` は無く、ai-agent-rules のフック (記録のコピー・Vault の注入) はクラウドに入っていない。skill も入っていない
- [未] 他の PC で、ルール (clone ・ 参照先のパス) をどう用意するかを決める
- [未] skill とフックをホームの設定へ入れる道具を作り、ルールで自動実行させる。張っていなければ張り、張ってあれば何もしない (冪等)。いつ実行させるか (セッション開始・ルールの更新の後 等) を決める (11/06 利用者の指摘)
- [未] 新しいプロジェクトに、クラウドの入り口をどう入れるかを決める
- [着手] PlayWright を隣に clone し、`check-contrast` が Linux の VM とクラウドで動くかを確かめる。クラウドでは、ブラウザに環境の Chromium (`executablePath`) を使う見込み (11/07 利用者の指摘。ai-agent-tools は、クラウドでは入り口が clone 済み)。OCI の VM で試した (11/07): PlayWright は GitHub にリポジトリが無く (ローカルのみ)、clone できなかった。VM には playwright もブラウザも無い。動かすには、PlayWright を GitHub に上げるかどうかの判断が要る。同日、PlayWright から返事: LightSpeedC/playwright を 11/07 に作った (private、develop のみ)。clone には認証が要り、クラウドではセッションへの追加が要る。clone のあと npm install と playwright install が要る (クラウドでは playwright install を実行せず、環境の Chromium を使う)。OCI の VM で続けた (11/07): clone と npm install は通った。ブラウザは ubuntu 用が入った (OS が公式の対象外)。check-contrast は `PLAYWRIGHT_BROWSERS_PATH=0` を決め打ちしており、ブラウザを `node_modules` の下に入れ直す必要があった。Chromium は OS のライブラリ 11 個 (atk ほか) が足りず起動しない。足すには sudo dnf install が要り、利用者の判断待ち。PlayWright 側には、bin の実行権限・package-lock.json が無い・"type" の警告がある。利用者が 11 個を入れたあと、OCI の VM で check-contrast が動いた (11/07。仕込んだ低コントラストを検出し、実際の資料は明暗とも OK)。手順: gh repo clone → core.fileMode false → bin に chmod +x → npm install → `PLAYWRIGHT_BROWSERS_PATH=0 npx playwright install chromium` → sudo dnf install (11 個)。クラウドは未確認。PlayWright 側への Linux 対応の依頼 4 点 (実行権限・package-lock.json・"type" の警告・USAGE に Linux の手順) は、20261011-claude-code-setup が利用者の指示で送った。VM の手順は、そちらの r261012-01 の「skill を入れる」「PlayWright 共有環境を入れる」にある。クラウド (0000-work) でも試した (11/07): そのままでは動かず、node_modules に環境のブラウザ (revision 1243) へのリンクを張り、除外を変えると動いた (1.01:1 を検出)。原因は、ブラウザの置き場の決め打ち、対象が /tmp の下だと全 HTML を除外すること、版のずれ (プロジェクト 1.65.0、環境 1.63.0)。0000-work が利用者の指示で PlayWright #02 に直しを依頼した。PlayWright の直しを待つ
