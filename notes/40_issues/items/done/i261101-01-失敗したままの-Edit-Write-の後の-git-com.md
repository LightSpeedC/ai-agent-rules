11/01 に 20261019-file-manager から依頼を受けた (#1727)。向こうで、Edit の失敗を見ずに git commit し、壊れたファイルが入った (向こうの振り返りの 413-A)。commit の前に会話の記録を調べ、失敗したままの Edit・Write があれば止める PreToolUse フックを、claude-hooks に組み込む。サンプル (`guard-commit-after-failed-edit.ts`) は向こうが用意済み。置き場は利用者から伝えられる。登録と試験の案・確かめていないことは、サンプルの頭のコメントにある。

11/04 に 20261019-file-manager から、失敗した Edit の直後の `git commit --dry-run` が止まらなかったと報告を受けた (#1783)。こちらで再現した。**失敗した Edit と commit を、同じ応答で並べて呼ぶと止まらない**。Edit の結果が会話の記録に入る前にフックが走るためとみられる。さらに、そのとき通った commit が区切りとして記録され、それより前の失敗の印が全部消えるため、続く commit も止まらなくなる。`--dry-run` も、同じ commit として区切りにしてしまう。向こうが尋ねた「止める条件」(相手のファイルが commit に載るときだけ ・ `--dry-run` は除く) は、いまのフックは見ていない。条件を変えるかは利用者の判断。

**やること**

- [済] 利用者からサンプルの置き場を聞き、読んで計画を立てる (11/01 計画 [i261101-01-失敗したEditの後のcommitを止める](../../../10_plan/i261101-01-失敗したEditの後のcommitを止める.md) を立てた。決めることは 3-A ・ 4-A ・ 5-A。承認済み)
- [済] テストを先に書いて組み込み、`settings.json` に登録する (11/01 ❌Red 4 件 → node ・ bun とも 140 件 ✅Green。登録して試走済み)
- [済] 実環境から確かめる (11/03 こちらで、別の応答に分けた場合の止まる ・ Read の後は通る、を実測)
- [済] 引き取ったことを依頼元へ知らせる (11/04 #1782 を送った。向こうの返事は #1783)
- [済] 同じ応答で並べた場合と、`--dry-run` の扱いを、どう直すか決める。`--dry-run` は 14-A で実装済み。並べた場合は、11/05 に 15-A (失敗を状態ファイルに書き、commit の前に読む) を選んだ。PostToolUseFailure があることは公式資料で確かめた。11/05 に仮の測定フックで測った結果、**15-A は成り立たない**: old_string が合わずに失敗した Edit は `PreToolUse` も `PostToolUseFailure` も走らず、同じ応答の呼び出しは、commit の `PreToolUse` の時点では 3 秒待っても会話の記録に入っていない (調査 r261105-01 の第 3 章)。測定フックは外した。案を出し直し、11/05 に 21-A (共通ルールに「Edit・Write と commit を同じ応答に並べない」と書く。暫定対策。恒久対策は、フックからは無い) を選んだ。11/05 に 14-A の「結果がまだ記録に無い Edit」を探す部分 (働かないと分かった) を消した (全件 168 件 ✅Green)。11/05 に 21-A を共通ルールの「修正は1点ずつ、確認を重視」へ反映した。同日に public へ周知した (#1794)。依頼元の確認も取れた (#1793)。
- [済] 原因と条件を依頼元へ返信し、確認を得る (11/05 #1792 を送り、#1793 で close でよいと返事)
