i261119-02 (存在しないパスの失敗で印が解けない) のコードレビュー (2026-11-19、サブエージェント) で残した穴。今回は直さず、起きうる条件だけ記録した。(1) シンボリックリンク・8.3 の短い名前・subst (W: と C:/work) の表記ゆれで、失敗と解く操作のキーが別になり、印が解けない。(2) Edit も Read も権限 (permissions.deny 等) で拒否されるファイルの失敗は解けない (稀)。(3) 巨大ファイル・バイナリの Read が上限で失敗する場合の扱いは未確認。(4) フックの deny の結果が is_error で記録されなければ、1 回止めたあと次の commit で印が消える (推測、未実測)。(5) git.exe commit・& git commit・bash -c は isCommit に当たらず止めない (抜け道)。(6) 『同じ失敗で N 回止めたら通す』出口は、利用者の判断が要るため足していない (guard-handoff-delete には、決定 451-B で同じ出口を入れた。守りが弱くなるが、抜け出せなくなる穴は消える)。やること: (1) 実際に起きたもの・起きうるものを選び、直す順を決める (利用者の判断) (2) (6) を入れるかを選択肢で聞く (3) 直す前に、今ある動き (失敗したままの Edit の後の commit を止める・cwd の外とディスクに無いパスは数えない) を試験で守る。優先度は低い (起きていない穴)。
