11/02 に 20261019-file-manager から報告を受けた (#1743)。向こうのセッションの記録は 564 MB あり、node の `readFileSync(…, 'utf8')` が `Cannot create a string longer than 0x1fffffe8 characters` で失敗した。読めないときは通す作りのため、止まらずに黙って通っている。記録を丸ごと読むのは `guard-english-before-tool.ts` (16 行目)・`require-japanese.ts` (21 行目)・`guard-commit-after-failed-edit.ts` (62 行目) の 3 つ (11/02 に Grep で確かめた)。英語の 2 つは末尾だけ読めば足りる見込み。commit の前の確かめは、前の commit より後の記録が要るため、読み方を決める必要がある。

**やること**

- [未] 読み方 (末尾から何バイト読むか・足りないときにどうするか) を決め、計画を立てる
- [未] 大きな記録で通ってしまうことをテストにし、❌Red を見てから直す
- [未] 報告元 (20261019-file-manager) へ結果を返信し、検証を依頼する。OK が出るまで「済」にしない
