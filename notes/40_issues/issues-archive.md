## 共通ツール

### `i260910-02` 公開前検査ツールへの組み込みを依頼する ✅ **済**

public のリポジトリへ公開する前に、個人名・実体パス・認証情報・顧客名が混ざっていないかを機械で止めたい。**公開前検査は共有ツールで他プロジェクトのものなので、こちらでは直せない**。何をどう直すかを伝えて、向こうで対応してもらう。実装先は `check-public`（プロジェクトを問わず共通）になった。

### なぜ共有ツール側に入れるか

- **公開資料を作るプロジェクトが他にもある**。共有ツールに入れれば、そのすべてが守られる
- ルールの生成処理にも同じ検査を入れる。**片方が漏れてももう片方で止まる**
- 公開してよいかを人が毎回判断する形にすると、ルールの追加は日常的に起きるので必ず漏れる

### 伝える検査の内容

| 検査 | 対象 | 除外するもの |
|---|---|---|
| メールアドレス | `[\w.+-]+@[\w-]+\.[\w.]+` | — |
| 実体パス | `C:\Users\` の直後が実名 | `<username>` などのプレースホルダ |
| 認証情報 | `password` `passwd` `secret` `api_key` `token=` | コード例の変数名は誤検出しやすいため要調整 |
| 除外語 | プロジェクトごとの語リスト（顧客名・案件名・内部システム名） | — |
| 異体字 | キリル・ハングルの混入。日本語の中に紛れると目視で気づけない | — |
| 実名の照合 | git の author とローカルユーザー名が本文に出ていないか。環境から取れるので名前をリストに書かずに済む | — |

> [!CAUTION]
> **除外語のリスト自体は Git 管理外にする**。顧客名や案件名を並べたファイルが公開されては本末転倒になる。**先頭 `_` のファイル**にすれば全階層で管理外になる。リストが無いときは除外語の検査だけを飛ばす形にする。
