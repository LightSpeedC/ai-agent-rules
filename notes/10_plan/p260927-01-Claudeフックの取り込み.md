Mac・Linux でも動かす予定があるため、**Windows専用の ps1 をそのまま持ってくる案は撤回**。フック本体をこのプロジェクトで TypeScript として最初から書き直し、`~/.claude/settings.json` はこちらを直接参照する形にする。

## 1. 目的

`~/.claude/hooks/` の ps1 は実体がホームディレクトリにあり、git 管理外・バックアップ対象外になっている。加えて Windows PowerShell 専用のため、Mac・Linux では動かない。**このプロジェクトを実装の置き場とし、フック本体を最初からクロスプラットフォームな言語で書く**ことで、OS を問わず同じソースが動く状態にする。

## 2. 現状

`~/.claude/hooks/` に2本の ps1 があり、`~/.claude/settings.json` の `hooks` 設定から `pwsh -NoProfile -File` で呼ばれている。

| ファイル | 役割 | 呼び出し元イベント |
|---|---|---|
| `copy-session-jsonl.ps1` | 会話ログ（JSONL）をプロジェクト直下 `etc/history/jsonl/` へコピーする | SessionStart・Stop |
| `load-obsidian-memory.ps1` | Obsidian Vault の `memory/!memory.md` をセッション開始時に読み込み、`additionalContext` として注入する | SessionStart |

> [!NOTE]
> **注意点**: `load-obsidian-memory.ps1` には Vault の固定パス（`N:\Obsidian\Vault\memory\!memory.md`）が1箇所ある。`C:\Users\` 配下ではないためマスク対象外だが、別PC・別Vaultではこの行を書き換える必要がある。

### settings.json 側の登録

ps1 本体だけでなく、`~/.claude/settings.json` の `hooks` ノード（呼び出しイベント・コマンド行・timeout）も同じく git 管理外。書き直し後は、このノードの中身自体を書き換える（後述）。

## 3. 設計方針

### 実装言語

コーディングルール「使用言語（Node / Bun）」の優先順位（`ts` > `mjs` > `cjs`）に従い、**TypeScript（`.ts`）で書く**。Node・Bun ともに Windows・Mac・Linux で動き、`.ts` を型チェックなしでそのまま実行できる。使うAPIは `node:fs`・`node:path`・`node:os` 等の標準モジュールのみで、OS 依存のコードは書かない。

### 実行コマンド

`node <path>` で起動する。bun が無い環境でも動かすため、**node を標準にする**。node は Win・Mac・Linux で動くため、OS ごとにコマンドを変える必要がない。標準モジュールだけで書くので、bun で `bun run <path>` と起動しても同じファイルが動く。**切り替え用のラッパー（cmd・sh）は作らない**。`bun:ffi` 等は使わないため、「bun と node で FFI を使うとき」の使い分け実装も不要。

手元（Windows）の node v26.10.0 で、型注釈つきの `.ts` を `node <path>` で直接実行できることを実測した。**node が `.ts` を直接実行できる最低バージョンは未確認**で、手順3で確認する。

### 置き場

`tools/80_ops/claude-hooks/` に置く。

| ファイル | 役割 | 呼び出し元イベント |
|---|---|---|
| `copy-session-jsonl.ts` | 会話ログ（JSONL）をプロジェクト直下 `etc/history/jsonl/` へコピーする | SessionStart・Stop |
| `load-obsidian-memory.ts` | Obsidian Vault の `memory/!memory.md` をセッション開始時に読み込み、`additionalContext` として注入する | SessionStart |

### 設定は「コピー」ではなく「直接参照」にする

ps1 のときのような「`~/.claude/hooks/` が正で、このプロジェクトへ手動コピーする」形はやめる。**このプロジェクトの ts ファイルを正とし、`~/.claude/settings.json` の hooks コマンドがこのプロジェクトのパスを直接指す**ようにする。同期の手間そのものが無くなる。

```json
"command": "node \"W:/ai-agent-rules/tools/80_ops/claude-hooks/copy-session-jsonl.ts\""
```

### Obsidian Vault のパス

旧 ps1 はパスを1行に決め打ちしていた（`N:\Obsidian\Vault\memory\!memory.md`）。OS が変わるとこの形式のパスは使えないため、**環境変数 `AI_AGENT_OBSIDIAN_VAULT` から読む**。未設定・パスが存在しないときは、旧実装と同じく何も注入せず正常終了する。

### 結果の表示

フックの結果を、ユーザーに見せる。標準出力の JSON の `systemMessage` を使う（モデルへ渡す `additionalContext` とは別）。

- **SessionStart**: 結果を常に表示する。
- **Stop**: 失敗したときだけ表示する。Stop は応答のたびに走り、成功を毎回出すと 1 行ずつ増えるため。
- 絵文字は共通ルールの結果の絵文字に揃える。

| 場面 | 表示 |
|---|---|
| メモリの注入に成功 | ✅ Obsidian メモリを注入した |
| メモリを渡した（再開のみ。同じ内容が会話にあれば取り込まれない） | ✅ Obsidian メモリを渡した（再開では、会話にあれば取り込まれない） |
| 環境変数が未設定 | ⬜ Obsidian メモリ: 環境変数が未設定のため注入なし |
| Vault に `memory/!memory.md` が無い | ⬜ Obsidian メモリ: !memory.md が無いため注入なし |
| メモリの読み込みに失敗 | ❌ Obsidian メモリの読み込みに失敗した: <理由> |
| 会話ログのコピーに成功 | ✅ 会話ログを N 件コピーした |
| コピーに失敗 | ❌ 会話ログのコピーに失敗した: <理由> |

`systemMessage` が画面でどう見えるかは、手順 10 で確認した（再開時にも 2 行が出る）。

表示の先頭には、絵文字に続けて、日付（月/日）と時刻（時:分、JST）を付ける（例: `✅10/04 00:50 Obsidian メモリを注入した`）。上の表は、日時を除いた文言を示している。

画面（Claude Desktop）では、再開直後にツール呼び出しが続くと、フックの表示は、同じターンのツール呼び出しと同じ折りたたみグループに入り、ターンの途中のテキストも一緒に畳まれる（見えるのは、最後の応答だけ）。再開後の作業が無いセッションでは、表示はそのまま残る。クライアントの仕様で、フックの出力からは変えられない。再開直後に 1 行のテキストを先に出す運用も試したが、一緒に畳まれて効かなかった（2026-10-04）。現状維持とし、展開すれば読める。

再開（`--continue` / `--resume`）では、`additionalContext` が会話にある分と同じだと、同じ回の `systemMessage` ごと捨てられる（Claude Code の重複排除。anthropics/claude-code の issue 96698）。そのため `copy-session-jsonl` は、SessionStart で、毎回違う開始時刻を `additionalContext` として一緒に渡す。会話に積むのは 1 行だけで、Stop には付けない。
