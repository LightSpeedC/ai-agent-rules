共有リポジトリの同期（shared-sync）

Obsidian Vault と ai-agent-rules の共通ルールは、どちらも複数のセッション・PC・クラウドから書き換えられる。同期（commit・pull・push）を共有ツール shared-sync 1 本に寄せ、clone の中では排他のロックで 1 本ずつ、clone の間では pull --rebase で取り込む。

目的

複数のセッション・PC・クラウドが同じリポジトリを書き換えても、書きかけの変更を壊さず、取りこぼさずに、GitHub と同期できるようにする。手順はスクリプト 1 本に閉じ込め、リポジトリや書き手ごとに作り方がばらつかないようにする。

現状と問題

Obsidian Vaultai-agent-rules の共通ルール
同じ clone の書き手全プロジェクトのセッション全プロジェクトのセッション
ほかの書き手別の PC・クラウドの clone別の PC・クラウドの clone
今の同期各セッションの Stop フック。書き手は書く前に fetch・rebase するこのプロジェクトの cron が commit → push。pull はしない
起こりうること書きかけがあると rebase が止まる（2026-10-18 に起きた）。autostash で通すと、共有の作業フォルダから書きかけが一時的に消える。Stop フックが並んで走るほかの clone から先に push されていると、push が拒否されて止まる

git の index.lock は、コマンド 1 つの間しか効かない。commit → pull → push の一続きの途中に、ほかのセッションの commit が割り込むのは防げない。

同じ clone を書き換えるだけなら、書く前の rebase は要らない。rebase が要るのは、ほかの clone から push された分を取り込むときだけで、同期する 1 か所が行えば足りる。共通ルールの運用（書き手は git に触らず、cron 1 か所が同期する）は、この形になっている。

設計

役割の分け方

範囲受け持つもの
同じ clone の中排他のロック。同期を同時に 1 本だけ走らせる
clone の間（PC・クラウド）git pull --rebase。ぶつかったら止めて報告する
書き手ファイルを書き換えるだけ。git に触らない（fetch・rebase・stash もしない）

置き場と呼び方

  • 共有ツール（ai-agent-tools の bin/）に shared-sync を置く。TypeScript で書き、cmd と sh の入り口を付ける（クラウドで動くのは sh 版だけ）
  • 名前に git- を付けない。PATH の git-<名前> は git のサブコマンドとして扱われ、git-sync という公開ツールも既にある
shared-sync "<リポジトリ>"                     # 変更をすべて載せる
shared-sync "<リポジトリ>" <パス> [<パス> …]     # 名指しのパスだけ載せる
使う側呼び方呼ぶ者
Obsidian Vaultリポジトリだけを渡す（環境変数 AI_AGENT_OBSIDIAN_VAULT の値）。未設定なら呼ばないStop フック
ai-agent-rulescommon-rules.md と rules を名指しする（ローカルルールの決まり）cron

処理の流れ

#処理失敗・競合のとき
1ロックを取る。.git/shared-sync.lock を排他で作り（openSync(path, "wx")）、ホスト名・pid・開始時刻を書く作れなければ中を読む。同じホストで pid のプロセスが無い、または期限を過ぎていれば残骸として消して作り直す。ホスト名が違うときは期限だけで判断する。どちらでもなければ、3 秒おきに取り直す。9 秒たっても取れなければ（初回を含めて 4 回）、「同期中のため飛ばした」と出して終了コード 0
2載せる対象に変更があれば、git add（全部か、名指しのパス）して commit。メッセージは shared-sync yyyy/mm/dd hh:mm:ss（JST）失敗したら止めて終了コード 1
3git pull --rebase。名指しのときは、名指し以外の commit 前の変更が作業フォルダに残っていても止まらないようにする浅い clone で失敗したら git fetch --unshallow してやり直す。ぶつかったら git rebase --abort で戻し、ぶつかったファイル名を出して終了コード 2。commit は手元に残る
4git push失敗したら終了コード 3（認証で止まったときも同じ。直し方は共通ルール「push が認証で止まったら」）。commit は手元に残り、次の回に送られる
5finally でロックを放す。中のホスト名と pid が自分のときだけ消す―

守ること

  • Node の標準モジュールだけで書く。Windows・Linux・Mac・クラウドで同じソースが動くようにする
  • git の呼び出しにはすべて timeout を付ける（共通ルール「同期 API は、そのプロセスの非同期処理を止める」）
  • 日時は Asia/Tokyo を指定して作る。クラウドの時計は UTC
  • 出力は何をしたかの 1 行だけ（例: shared-sync: commit 1 件・push 済み）
  • ほかのセッションの変更を消す操作（reset --hard・stash・checkout --）はしない
  • 認証は呼ぶ側の環境に任せる（Windows は gh、クラウドは環境が用意するもの）。git の設定は書き換えない

テスト

tmp/ に裸のリポジトリと、その clone を 2 つ作って使う（別の PC の代わり）。本物の Vault・共通ルールには触らない。テストを先に書く。

  • 変更が無いときは commit しない
  • 変更があれば commit して push する
  • 名指しのときは、名指し以外の変更を載せない
  • 同じ clone で同時に 2 本を走らせても、同期の一続き（commit → pull → push）が重ならない
  • ロックが 9 秒以内に放されれば、待っていた側が取り直して進む。放されなければ飛ばす
  • 残骸のロック（pid が無い・期限切れ・ホスト名が違って期限切れ）を消して進む
  • もう一方の clone が先に push していても、取り込んでから push する
  • rebase がぶつかると止まり、手元の commit と変更が残る

openSync の wx の排他と process.kill(pid, 0) による生存確認は一般的な仕様に基づく。Windows・Linux・Mac では未検証で、上のテストで確かめる。

ルールの書き換え

共通ルール「Obsidianメモリ連携ルール」＞「同期」を、次の文面に置き換える。ロックの中身はルールに書かず、shared-sync に閉じ込める。

## 同期

- **書き手は git を使わない**。Vault のファイルを書き換えるだけにする（fetch・rebase・stash もしない）
- **同期は `shared-sync` だけで行う**。Stop フックが呼ぶ。Vault に限った例外で、「重大な操作の確認方法」の対象にしない
- **`shared-sync` が止まって報告したら、ほかのセッションの変更を消さずに、利用者に伝える**

ローカルルール「chat 待受け・共通ルールの追随の点検」は、commit・push の手順を shared-sync の呼び出しに置き換える。

クラウドでの扱い

クラウドでは、commit・push は明示の指示を待つ（共通ルール「クラウド作業のルール」）。クラウドの Stop フックや cron から自動で呼ぶかは、決めることの 5 で決める。手で呼ぶだけなら、今の決まりのままで足りる。Vault を使う環境では、環境変数 AI_AGENT_OBSIDIAN_VAULT を設定する（クラウドでは cloud-session-start で設定）。
