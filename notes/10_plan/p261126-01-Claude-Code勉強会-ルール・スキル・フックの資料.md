# p261126-01 Claude Code 勉強会 (ルール・スキル・フック) の資料 (読み物 9 本。プレゼンは後)

このプロジェクトが持つ共通ルール・スキル・フックを、AI エージェント (特に Claude Code) を使う開発者の同僚に学んでもらう勉強会の資料として、読み物の HTML と、それを元にしたプレゼン用の HTML (後で pptx) を作る計画。入力: `rules/`・`skills/`・`tools/80_ops/claude-hooks/`・失敗の記録 (課題・調査)・共有ツールと ai-chat-lite の README (読むだけ)。出力: `docs/` の読み物 9 本・構成案・プレゼン 1 本の HTML と、共通の CSS・JS。

## 1. 作るもの

**一言で**: このプロジェクトのルール・スキル・フックを、Claude Code を使う開発者の同僚が「少しずつ入れていける」ように、失敗の話を軸にした読み物とスライドにする。

#### `docs/` の読み物 9 本 (01〜09。名前は作業 3 で決める)

- 読み物。1 本が 1 つの段階 (ツールとチャットも、必要になった段階の章)。前へ・次へ・目次のバッジで順に読む。「いまここ」の旗は、右端に縦に固定し、各ページの段階の印から位置を決める
- **作る順**: 1

#### `docs/ZZ-構成.html` (名前は案)

- 構成案。全体像とロードマップの図、対象読者、章立ての意図、書き方の方針
- **作る順**: 1

#### `docs/勉強会-プレゼン.html`

- スライド。読み物の各段階を、1〜3 枚に要約する。矢印キー (と画面の押し) で進む。「いまここ」の旗は、下端のバーで常時出す
- **作る順**: 2 (読み物のレビューの後)

#### pptx

- プレゼン HTML の見出しを 1 枚ずつ写す。別の計画にする
- **作る順**: 3 (後で)

全部 `docs/` 配下。CSS は `docs/css/style.css`、JS は `docs/js/` に置いて共有し、CDN を参照しない (CSS が読めないときの代替色は、`<link>` の前に書く)。章アクセントと目次は、各 HTML に書く。

資料を作った時点で、root の `README.html` から資料へリンクを張り、資料から README へ戻るリンクを張る (相互リンク。後回しにしない)。README.md は `html2md` で作り直し、`check-markdown` で崩れを確かめる。

**画面の作り**: JS が無効な環境は想定しない (11/26 の指示)。無効時の逃げ道は作らず、試験・撮影の対象にもしない。キャラの絵は、揺れる・傾くなど、動いてよい (`prefers-reduced-motion` の設定では止める)。狭い画面では、旗を縦固定から上端の横バーに切り替える。

## 2. 構成 (案)

### 全体像とロードマップ

読み物の先頭に、全体像の図 (ルール・スキル・フックと、共有ツール・ai-chat-lite の関係) と、ロードマップの図 (9 つの段階の道) を置く。ロードマップは、各段階の駅を結ぶ道で、「いまここ」の旗が、読んでいる段階の駅に立つ。読み進める (スクロール・スライドを進める) と、旗が次の駅へ動く。

全体像は章にしない。紺 1 色のバー (虹色の章に数えない) にして、9 つの段階を 9 章にする (467-B。章の数は 473-A・474-A で 6 から 9 に変わった)。バーの位置と見た目は、作業 3 の図の一覧で決める。

### 9 つの段階

段階ごとの中身 (規模・入れる決まり・失敗・図) は、下の「9 段階の下書き」に書く。順は、学ぶ人の成長の順 (小→大)。ツールとチャットは、必要になった段階の章にする (473-A)。

失敗の例は、実際の記録 (課題・調査・フックの止めた記録) から拾う。**実在の個人名・社名・実体パスは使わない** (460-A)。同じ失敗の話は、1 つの段階に 1 回だけ出す。

### 各段階の書き方

1. 案内役のキャラが、失敗を 1 つ見せる (SVG 図、軽い動き付き)
2. 足した決まりを、1〜3 行で示す
3. 使い方・見る場所 (どの章・どのコマンド・どの README) を 1 行で示す
4. 次の段階への一言

**キャラ**: ルールちゃん (段階 1)・スキルちゃん (段階 5)・フックくん (段階 8) の順に登場する。関係は「ルールが増えると読み込みが重くなり、スキルに分ける。文だけで止まらないものを、フックが止める」と、全体像の図に 1 度だけ示す。

### 9 段階の下書き (素材の洗い出しと、3 プロジェクトの履歴から。作業 3)

事例は、共有ツール・チャット・ファイルマネージャの履歴を、利用者の許可 (11/26) で読むだけのサブエージェントが拾った。数字と日付は報告の引き写しで、**書くときに出典 (課題・調査・commit) を開いて確かめる。数 (件数・サイズ・回数) も再計測する**。会話の記録 (JSONL) は読んでいない。段階への割り当ては仮で、同じ話は重ねない。

**出典の書き方 (5 回目のレビューの指摘)**: 下書きの番号は、プロジェクト名が付いていない。出どころは、03〜05 が主に ai-agent-tools、06 が ai-chat-lite、07・08・09 がファイルマネージャとこのプロジェクト。書くときは「プロジェクト名 + 番号」に直す (決定番号も「決定 (プロジェクト名)」の形)。読み物の本文には、番号でなく事実を書き、番号は構成案 (`ZZ-構成.html`) の出典表にまとめる。読者は、他プロジェクトの番号を開けない。

**各段階の絞り方**: 失敗の一コマは、主役を 1〜2 件にし、残りは「小ネタ」「補足」に降ろす。ファイルは、読み物に書く段階で、失敗を項目ごとの子の箇条書きにし、各項目の末尾に出典を揃える。

**実測 (サブエージェントの報告。再計測は読み物を書くときに行う)**: `rules/` 16 ファイル・`skills/` 14 本・フックのファイル 26 本・`settings.json` への登録 19 コマンド (PreToolUse 9・PostToolUse 1・UserPromptSubmit 2・SessionStart 1・Stop 6)。共通ルールの常時読み込みは約 198 KB (トークン数は `/context` の表示で約 7.5 万) で、スキルへ分ける前の値。読み物に載せるときは、日付を付けて再計測する。

## 3. 見せ方

- **SVG 図**: 共通ルール「HTMLデザインルール」の図の決まり (箱は下から上へ明るくなる縦グラデーション・id はページで一意・文字は白) に従う。軽い動き (ふわふわ・ぴょこぴょこ) は CSS だけで付け、`prefers-reduced-motion` の設定では止める
- **「いまここ」の旗**: 読み物は右端に縦に固定。プレゼンは下端のバーに固定。段階の色は、章の虹色 (9 章の色相: 280 / 245 / 210 / 175 / 140 / 105 / 70 / 35 / 0) に揃える
- **配色**: 背景は淡い色のみ。章の色は、共通ルールの虹色の決まりに従う。道具が作る HTML ではないので、暗い配色は持たせない
- **面白さ**: キャラの吹き出し・失敗の一コマ漫画 (SVG)。ただし、読み手の役に立たない自虐や制作の事情は書かない
- **スライドの動き**: 矢印キー・画面の押し・「いまここ」の旗の押しで移動。印刷用の見た目は付けない (pptx は別の計画)
