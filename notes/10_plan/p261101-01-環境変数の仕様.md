## 1. 目的

フックが読む環境変数を、共通ルール「仕様の書き方と置き場」の詳細仕様として 1 か所にまとめる。いまは README の節と表の行に分かれ、書いていない使い方もある。

## 2. 現状

| 環境変数 | 読むコード | 未設定のとき | README の記述 |
|---|---|---|---|
| `AI_AGENT_OBSIDIAN_VAULT` | `obsidian-memory.ts` (Vault の同期と注入) ・ `sync-obsidian-vault.ts` (Stop の同期) | 注入しない (「環境変数が未設定のため注入なし」と出す) ・ 同期しない (何も出さない) | 「環境変数」の節に `obsidian-memory.ts` の分だけ |
| `CLAUDE_PROJECT_DIR` | `jsonl-copy.ts` (会話ログの写し先) ・ `vault.ts` (未登録の判定に使うプロジェクト名) | 写し先は `.git` をたどった先 → `cwd`。プロジェクト名は `cwd` のフォルダ名 | `jsonl-copy.ts` の表の行だけ |

`~/.claude/settings.json` の `env` にある値 (`CLAUDE_CODE_USE_POWERSHELL_TOOL` ・ `GHIDRA_INSTALL_DIR` 等) は、フックではなく Claude Code ・ REA が読む。使い方は共通ルールの各章にある。

## 3. 設計

### 詳細仕様の中身

- 変数ごとに 1 節。誰が設定するか (利用者 ・ Claude Code) ・ 読むコード ・ 値の形 ・ 未設定のときの動き ・ なぜそうか
- 経緯は、課題 ・ 計画への番号で示す (i261008-01 ・ #1548 等)。履歴は書かない
- 扱う範囲は、決めることの 1 (B: フックが読む 2 つと、`settings.json` の `env` の 4 つ。6 つとも全部書く)

### ほかの資料

- フックの README の「環境変数」の節と、表の行の環境変数の説明は、詳細仕様へのリンクに置き換える (決めることの 2)
- root の README に、`50_spec` の章を足す。章は 5 → 6 になるので、色相を 6 章で振り直す (280 / 224 / 168 / 112 / 56 / 0)
- ローカルルール 4 章の表の「Vault の場所」の行は、ルールの値なので残す
