## 2. AI_AGENT_OBSIDIAN_VAULT

- **値**: Obsidian Vault のフォルダ。区切りは `/` ・ `\` のどちらでもよい
- **読むコード**: `obsidian-memory.ts` (SessionStart。Vault を同期し、`memory/!memory.md` と `projects/!projects.md` を注入する) ・ `sync-obsidian-vault.ts` (Stop。Vault を commit ・ push する)
- **未設定のとき**: `obsidian-memory.ts` は注入せず、「⬜ Obsidian メモリ: 環境変数が未設定のため注入なし」と出して正常に終わる。`sync-obsidian-vault.ts` は何も出さずに終わる
- **設定してあるが `memory/!memory.md` が無いとき**: 注入しない
- **なぜ**: Vault と連携していない PC ・ クラウドでも、フックを壊さずに置けるようにする。場所をルールに書かないため、ルールは変数名だけを指す (共通ルール「Obsidianメモリ連携ルール」)
- **注入文の表示**: 場所はユーザのホームを `~` に置き換え、区切りを `/` にして出す

## 3. CLAUDE_PROJECT_DIR

- **値**: セッションを始めたプロジェクトのフォルダ。Claude Code が、フックを起動するときに渡す
- **読むコード**:
    - `jsonl-copy.ts`: 会話ログの写し先 (`<プロジェクト>/etc/history/jsonl/`) の起点
    - `vault.ts`: Vault の `projects/` に、そのプロジェクトのノートがあるかを調べるときのプロジェクト名 (フォルダ名)
- **未設定のとき**:
    - `jsonl-copy.ts`: フックの入力の `cwd` から上へたどり、`.git` のあるフォルダを使う。無ければ `cwd` を使う。`cwd` も無ければ写さない
    - `vault.ts`: フックの入力の `cwd`、それも無ければフックのカレントの、フォルダ名を使う
- **なぜ**: `cwd` はセッションが `cd` すると変わる。サブフォルダに写すと、会話ログが散らばる (課題 i261008-01 ・ 依頼 #1548)

## 4. Claude Code が読むもの

いずれも `~/.claude/settings.json` の `env` に置く。

### CLAUDE_CODE_USE_POWERSHELL_TOOL

- **値**: `"1"`
- **効き目**: PowerShell ツールが使えるようになる
- **未設定のとき**: PowerShell ツールが無く、Bash ツールから `psh` で呼ぶ
- **なぜ**: 共通ルールは、コマンドを PowerShell で実行すると決めている (共通ルール「PowerShell ツールが無いときは psh で呼ぶ」)

### CLAUDE_SUBAGENT_BG_SHELL_MAX_MS

- **値**: `"43260000"` (12 時間 1 分)
- **効き目**: 名前から、サブエージェントが背面で走らせるコマンドの、時間の上限 (ミリ秒) と読める。**未確認** (Claude Code の資料で確かめていない)
- **値の理由**: chat 待受けの最大 12 時間より少し長くしたものと推測する。**未確認** (設定した経緯の記録が無い)

### CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP

- **値**: `"1"`
- **効き目**: 空きメモリが減っても、背面のコマンドを止めない
- **未設定のとき**: 空きメモリが減ると、Claude Code が背面のコマンドを止める。通知に「running low on memory」(メモリ不足) と出る
- **なぜ**: chat 待受けが止まらないようにする。メモリが十分な環境に限る (共通ルール「ai-chat-lite（AI 間チャット）の利用」)

## 5. REA が読むもの

### GHIDRA_INSTALL_DIR

- **値**: `"C:/Tools/reverse-engineering/ghidra"` (Ghidra を置いたフォルダ。実体のパスで、ユーザ名を含まない)
- **読む者**: MCP サーバ `rea` (`rea-agents`)。Ghidra で逆コンパイルするときに使う
- **置き場の理由**: もとは REA 専用の起動コマンドが設定していた。通常のセッションで REA を使うようにしたため、`settings.json` の `env` に移した (計画 [p261027-02](../10_plan/p261027-02-REA設定の通常セッションへの統合.md))。全セッションに渡るが、読むのは `rea` だけ
- **未設定のとき**: `rea` が Ghidra を見つけられない。**どう失敗するかは未確認**
