分かったこと (ネットの資料)

下の資料はブログなどの二次資料が中心。Claude Code の公式資料で確かめたのは、フックの種類だけ (次の章)。数値は経験則で、鵜呑みにしない。

事柄内容
取り込みでは減らない@ で取り込んだファイルは起動時にすべて読み込まれる。章に分けても、読み込む量は減らない。減るのは、条件で読み込むものだけ
条件付きの読み込み.claude/rules/ に置き、paths: を付けたものは、該当するファイルを触ったときだけ読み込まれる。paths: が無いと毎回読み込まれる。skill は必要になったときだけ本文が読み込まれる
長さの目安1 ファイル 200 行以下。毎回効く決まりだけを置き、手順や一部にだけ効く決まりは skill か paths: 付きに移す
増えると守られない規則が増えると、見落としが先に増え、次に無視される。公式の上限は無く、「150 行」などは経験則。ベンチマーク (IFScale) では、よいモデルが 150 規則あたりまで高い遵守率を保つとされる
止める手段破られては困る決まりは、文でなくフックや CI で止める

フックの種類 (15-A の調査。公式資料)

課題 i261101-01 (失敗したままの Edit・Write の後の git commit を止める) の 15-A は、失敗を状態ファイルに書き、commit の前に読む案。そのためのフックの種類を、公式のフックの資料で確かめた。

事柄分かったこと
失敗を知らせるフックPostToolUseFailure がある。ツールの呼び出しが失敗した後に走る。PostToolUse は成功したときだけ走り、失敗では走らない
入力の項目共通の項目に、tool_name ・ tool_input ・ tool_use_id が付く。PostToolUseFailure の項目の細部 (エラー本文の名前など) は、資料の該当箇所を読めておらず未確認
並べた呼び出しの順同じ応答で並べたツールの PostToolUse が、次のツールの PreToolUse より先に走るかは、資料に書かれていない (未確認)。同じ種類の事象に付くフックどうしは、並列で走る
まとまりの終わりPostToolBatch がある。並べた呼び出しが全部終わった後、次にモデルを呼ぶ前に走る。終了コード 2 で、ループを止められる

実測 (11/05、仮の測定フックを 3 本登録し、セッションを開き直して測った。測り終えて外した):

  • 成功した Edit は、PreToolUse と PostToolUse の両方が走った。
  • old_string が合わずに失敗した Edit では、PreToolUse も PostToolUseFailure も走らなかった (2 回とも)。入力の検査の段階で失敗し、フックに届かないとみられる。つまり、15-A の PostToolUseFailure では、この種類の失敗を拾えない。
  • 同じ応答で Edit と git commit --dry-run を並べたとき、commit の PreToolUse が走った時点の会話の記録には、同じ応答の Edit と commit の呼び出しは、まだ入っていなかった。3 秒待って読み直しても、入っていなかった (2 回目の測定)。入るのは、応答のまとまりが終わった後。
  • したがって、commit の PreToolUse から同じ応答の失敗した Edit を知る手段は、いまのところ無い。PostToolBatch (並べた呼び出しがすべて終わった後) は、間に合わない (commit は済んでいる) が、事後の警告には使える見込み。未測定。
